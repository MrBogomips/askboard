# As built: `accept-as-sent`

In code since `accept-as-sent` (Issue #263): "Accept as is" answers a question with no options whose widgets edit agent content with that content as the agent sent it, as one explicit click that takes the path of "Answer". The agent receives an answer marked `asSent: true`, with the open prompt's note, the input fields' `results` and the derived values, and no `changes` or `choice`. `ask-core` accepts it only where it is true. The card action beside the primary, never beside "Accept recommended" and with no key of its own, is the proposal's. The review decisions below (D-A, D-B) were taken by the coordinator under the PO's unattended hand-over, not by the PO's answer; the PO may revisit them.

**Behaviour to know.**
- The button is offered only on a question with no options that holds an item whose component registered an element shape, while the question is to do or in draft, the card shows the current revision, which the work names, with no item read-only (D-B), every result held is an input field's (D-A), and every draft value equals the item as sent by the contract's `elementChanges`. A type whose chunk has not registered its shape gives no button until it does.
- It is disabled (not hidden) while a field blocks, a notice waits or a command of the card is on its way.
- An opened Snapshot has no actions row, so it named no answer; `ActionsRow` draws the answer line alone there for an answer accepted as sent, which no chosen option would otherwise show.
- **D-A, input fields' results travel.** Results of the types that declare a `fieldCheck` (TextField, NumberField, MoneyField, DateField, Toggle, PickField) go beside `asSent` in the act, the event, the board state and `fetch`; the field checks still run, so a required field left empty keeps the button disabled with "Complete {label} first.". A result of any other type (an Approval's verdict, a Ranking's order) hides the button in the view and is refused by `asSentProblem`, which reads the item's type in the registry. The view tells an input field by the fact `inputField` (`ComponentFacts`), registered by the six field chunks only and held equal to the registry's `fieldCheck` by `packages/widgets/test/component-facts.test.ts`; a chunk's `check` is no stand-in (the Document review registers one). No version moved for it.
- **D-B, current revision only.** After "Keep mine" the card shows an older revision, or the current one with items read-only; an acceptance there would claim content the user did not see. The view offers the button only on the current revision (`onCurrentRevision`), `answer` re-checks it, "Keep mine" releases a held acceptance, and Submit sends none that names an earlier revision. "Keep mine" releases through `releaseHeld`, so an undo held beneath the acceptance is held again. The board page's `asSentProblem` refuses an `asSent` answer whose `rev` is not current too. The core refuses an `asSent` answer whose `rev` is not current, naming the current revision. "Reload, losing my work" shows the current revision, where the button is offered again.
- An asSent answer beside values equal to what was sent is accepted and keeps none; any other value refuses it (`content`, "an answer accepted as sent holds values that differ from the content as sent").
