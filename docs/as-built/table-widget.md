# As built: `table-widget`

In code since `table-widget`: one registry entry in `contract` and `widgets` (`table`, folder `table/` in each, appended to `WIDGET_TYPES` after the PickField, the last entry of the base it is rebased onto): `contract/src/widgets/table/` holds the props schema (`table-props.json`), the changes schema (`table-changes.json`, narrowed to `add`, `remove` and `set`), the constants (`TABLE_MAX_ROWS` 200, `TABLE_MAX_COLUMNS` 10, `TABLE_TEXT_MAX_CHARS` 500, `TABLE_FORMULA_MAX_CHARS` 500, `TABLE_FIELD_PATTERN`, `TABLE_SHAPE` = `{elements: "rows"}`, `TABLE_ANSWER_DERIVED`), the plain checks (`tablePropsProblems(props, origin)` with origin `agent` or `edited`, `tableCellProblems`, each column checked by its input atom's own props and result checks over a projection), `derived.ts` (the addresses an answer's derived values may name: `<field>` for a total, `<row>.<field>` for a formula cell) and the wording; `numberFieldBound`, `moneyFieldBound` and `dateFieldBound` beside the atoms' result checks give the bound a value breaks, which the atoms' readers and the Table's reader word. A Table has columns (`text`, `number`, `money` in one currency, `date`, `toggle`; `formula` on a number, money or date column, `total` on a number or money column), rows with IDs, and `fixedRows`; its answer holds `changes` (a `set` of `item.row.field`, an `add`, a `remove`) and derived values, never a result. In `compute`: `ROW_REFERENCE_PREFIX` (`@`) and the row form `[@field]`, read by the lexer and resolved on a child's field to the same child (any other node: `missing-reference`); `FieldsItem.columns`, whose formula runs on every row, parsed once per text in a build; a column formula that holds a wildcard or a range is `over-limit` (single reads only); one warning per column and kind, addressed `item.*.field`, which `core`'s `formulaWarnings` passes through unchanged; `BOARD_SOURCES.table` (`table-source.ts`: totals as `SUM([item.*.field])`, or `0` over no rows). In `core`: the Table's `changes` checked against its schema and rebuilt by the round trip, derived values checked against the Table's declared addresses, and a Table's formula warnings at send time, with no product change beyond the registry. The board protocol's draft record gains `cellEntries` (item ID, then `row.field`, each text 1 to `ENTRY_MAX_CHARS`, at most `CELL_ENTRIES_MAX` = 2,000 to an item), kept beside the draft's values and entries, restored after a reload, dropped with the item's value (an update that removes the item, "Reload", a "Keep mine" whose value does not fit) and counted as unsent work. In `view`: `ItemProps.cellEntries` and `onCellEntriesChange` appended to the port, `shell/cell-entries.ts` (the store's functions and `entriesWithCells`, which gives every entry reader an entry under the Table's ID while any cell holds one, so "Answer", "Send and switch", Submit, the held mark and the Tabs mark need no change of their own), and `ENTRY_ITEM_TYPES` with `table`, which the field block (`field-block.ts`) reads. In `widgets`: `table/model/` (`columns`, `read`, `edits`, `focus`, `marks`, `derived`, `fits`, `text`: plain modules, tested without a DOM) and the component (`index.tsx` registers `{shape, name, valueFits}`; `widget.tsx`, `grid.tsx`, `row.tsx` with `row-equal.ts` so an edit redraws one row, `cell-editor.tsx`, `toolbar.tsx`, `total-row.tsx`): AskBoard's own ARIA `grid` on a `<table>` with roving `tabIndex`, no new dependency, one Tab stop for the grid and one for the toolbar ("Add row" after the current row, "Delete row"), an editor on Enter, F2 or a double click that reads the text with the atoms' parsers and echoes the value, an on/off cell switched by Space, Enter, F2 or a click, cells and headers that wrap inside the frame (`overflow-wrap: anywhere`) while a wide grid scrolls inside it, the change highlight and the derived mark, and a formula problem shown once over the grid. `shownTable` shows a held value only while it fits the props (`tableValueFits`, the component's `valueFits`), else the agent's props; an open editor keeps the cell's value from when it opened and closes without a commit when the agent changes the cell, its column or its row (`editingStands`). `board-graph/recalc.ts` recalculates a Table's changed input cells in place when its columns and row IDs are unchanged (`InputChange` now holds `compute`'s `Scalar`). The view build holds the chunk `table` (`chunk-sizes.json`). `skills/askboard/references/widgets/table.md` teaches it. The bounds are timed on the worst form (200 rows, 10 columns, nine formula columns of 500 characters, all totalled) with `tools/table-timing.ts` (gates of design decision 13) and in the browser by `table-bounds.browser.ts`; the fan-out form's edit gate is 150 ms in WebKit, 100 ms in Chromium. Browser scenarios: `table.browser.ts`, `table-keys.browser.ts`, `table-session.browser.ts`, `table-snapshot.browser.ts`, the Italian Table in `languages.browser.ts`; the conformance case is in `edit-widgets.e2e.ts`. After a reload, while the card shows another revision than its work's, the Table is read-only with the line like the other edit widgets (`keep-mine-shown-revision`): `onCellEntriesChange` writes nothing for it and "Keep mine" drops its held cell entries, so none blocks "Answer"; its answer then carries no derived values. Versions: input format 1.12, output format 1.11, tool envelopes 1.12, board document 1.11 and board protocol 1.8, bound on 2026-11-08 on main 433b4d29 (form-widget merged, #64; main holds input format 1.11, output format 1.10, tool envelopes 1.11, board document 1.10 and board protocol 1.7), each one minor past it; the Snapshot data and the view manifest are unchanged.
