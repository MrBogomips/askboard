# As built: `result-bound`

In code since `result-bound` (Issue #98): the warnings of an `ask` or `update` result stay within their share of AD-6's 30,000-character result bound. `core/src/warning-bound.ts` holds `boundedWarnings(warnings, {max, room, closing})`, a pure function that keeps the longest prefix of a list whose JSON text, plus `room`, fits `max` and ends it with one closing warning for the first warning left out, counting the rest (kept + 1 + count equals the input). `boundedFormulaWarnings` (`core/src/graph-check.ts`) calls it with `FORMULA_WARNING_CLOSING_MAX_CHARS`, its output unchanged. `core/src/context/warnings.ts` adds `UNRESOLVED_WARNINGS_MAX_CHARS` (10,000), `closingUnresolvedWarning` (an ordinary `unresolved-pointer` warning keeping `itemId`, `pointer` and `reason` of the first left out, with a plural and a singular form, never counting 0), `boundedUnresolvedWith` (the closing builder as a parameter, the one path of the shipped code) and `boundedUnresolvedWarnings`; `unresolvedWarnings` returns the bounded list, so `Ask.update` and `contextWarnings` share it. The room is the larger of the closing warning at the list's count and at count 1, plus 1 for the comma before it, so the bound holds whatever the singular and plural words. The board document still marks every unresolved item, and `fetch` returns every pointer with its status.

Order of the warnings in an `ask` result: `no-hooks`, then the unresolved-pointer warnings, then the formula warnings, each kind closed by its own closing warning when cut; in an `update` result: unresolved pointers, then formula warnings, at most 20,000 characters. Worst totals measured through the session's tools (`server/test/mcp-tools/worst-ask.ts`): the worst `ask` the contract admits 16,055 characters (6,509 unresolved, 9,099 formula, 220 `no-hooks`, 229 envelope), 19,475 with the unresolved share filled, about 20,540 with a real board token and a 64-character ask ID. No `server/src` change. The `applied` list of `update` and the `collect` page of one large Submit are left open (Issues #113 and #114).

Versions: none moved, every constant equals `main`'s.
