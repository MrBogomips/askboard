# As built: `keyboard-shortcuts-help`

In code since `keyboard-shortcuts-help` (Issue #81): one source for the keys a widget takes, shown where they act and changeable by the user in the user file. `contract/src/keys/` holds the vocabulary and the checks: `KEY_VOCABULARY` (`vocabulary.ts`, the PO-approved keys included), `keyActionOf` and the `mod+alt` hold (`match.ts`; `mod+alt` is admitted in overrides only, and `keyTableProblems` in `check.ts` refuses it in a registry table), `ariaKeyShortcuts` (`aria.ts`), `parseKeyCombination`, `keyCombinationText` and the bounds `KEY_OVERRIDES_MAX_ACTIONS`, `KEY_ACTION_MAX_CHARS`, `KEY_OVERRIDE_MAX_COMBINATIONS` (`notation.ts`), `effectiveKeys`, `sameBindings` and `changedKeyActions` (`effective.ts`), `keyOverridesProblems` and `keyExitActions` (`overrides.ts`, defaulting to `REGISTERED_KEY_TABLES` in `tables.ts`), `KEY_TABLES_ON_BOARD` (`board.ts`, `["ranking"]`; each retrofit appends its types), and `quoteFileText` and `escapeFileText` for file text shown or written to stderr (`schemas/configuration/file-text.ts`). A registry entry gains `keys` and `help`; `packages/contract/test/keys-coverage.test.ts` lists each type without a table and why.

The configuration gains `keys` (user file only: `ask-core` drops a project `keys` with `project-keys-ignored`, and the whole of a user `keys` that fails the check with one `keys-not-applied` warning per problem, `core/src/config/rules.ts`); the board protocol's `settings` message gains the `keys` row and those two warnings, at most `SETTING_ROW_WARNINGS_MAX` per row; `setting` is unchanged and a board writes no key. In the view, `ViewUpdate.keys` carries the applied overrides (`view-protocol.ts`); `useKeyTable` (port, `catalog/keys/key-table.tsx`) gives the table in effect; `ComponentFacts.keys` registers a type's table; `KeyHint`, `KeysButton` and `useKeysPanel` are in `catalog/keys/key-help.tsx`; `KeysFrame` (`shell/keys-frame.tsx`) holds the panel and `KeysPanelBody` (`shell/keys-panel.tsx`) its content; the port's `keyPressOf` is the one press reader. In `widgets`: the Ranking's selection, check boxes, moves and toolbar (`ranking/`), `toolbarPressMove` (`shared/toolbar-focus.ts`, used by `shared/move-toolbar.tsx`), and `SelectBox` and `useCrowded` moved into `shared/`. The pure export `@askboard/view/strings` gives the skills the English action names. The generator writes a second skill: `generateHelpSkill` (`tools/build/skills/help.ts`, `help-keys.ts`) writes `skills/askboard-help/`, which the release and the benchmark's `EXPECTED_SKILLS` (`packages/bench/src/report.ts`) also know; `askboard` points to it, and the generator checks each example key file with `keyOverridesProblems`.

Chunks (`packages/view/chunk-sizes.json`, bytes, change against the previous record on main): `ranking` 29,960 (+60.2%), `shell` 221,386 (+10.3%), `radix` 145,894 (+6.5%, Tooltip), `board-page` 1,035,264 (+3.8%, the settings panel's Keys row and the key-override check, without the registry); every other chunk moved under 5%.

Versions bound: the configuration and the board protocol, each main's minor plus one (`CONFIGURATION_VERSION`, `BOARD_PROTOCOL_VERSION`); the final numbers and main's SHA are written here by task 7.1. No other set moved. No sentence of an earlier note became wrong.
