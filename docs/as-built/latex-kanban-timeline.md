# As built: `latex-kanban-timeline`

In code since `latex-kanban-timeline`: three registry entries in `contract` and `widgets`, one folder each (`latex`, `kanban`, `timeline`), each with its props, changes schema, checks, wording, `skill` text and component, and `skills/askboard/` teaches them. The LaTeX is one expression in a source field with a live preview, answered as one `set` of `expression`; the Kanban moves cards between columns by drag or "Move to…"; the Timeline moves milestones and ranges across lanes on the Gantt's time axis, with the time code now in `widgets/src/shared/time/` and the pointer drag in `shared/pointer-drag.ts`. In `contract`, `FieldsShape` (a shape of named fields of the item itself, addressed `item.field`, beside `ListShape` and `KeyedShape`) lets a whole field change by one `set`, and `widgetChangesProblems` checks each `changes` entry against the changes schema of its item's type: `core` refuses an answer whose changes fall outside it, appending nothing (NFR-10). In `view`, `ComponentFacts.valueFits` (a draft, a restored draft and "Keep mine" hold a value only where its item's type shows it on the item's current props, so an answer sends what the item shows, AD-10) joins `fits`. The LaTeX draws with KaTeX 0.19.1 (exact pin, in `widgets` only) with `trust` off and no macro that outlives its render; it refuses a macro definition, a KaTeX internal command (a name holding `@`), any command the item does not allow and a nest past `LATEX_NESTING_MAX_DEPTH`, with a field error that names it, and the agent's `ask` and `update` refuse the same sources. The board draws through KaTeX's documented `katex.render`, into an element outside the page, after the contract's scan, which also counts stacked combining marks (`latex-public-api`); the nesting limit comes from one measurement in Chromium and WebKit. Previews draw one at a time through a render queue, an edited item first. A chunk's package stylesheet goes through `CHUNK_STYLESHEETS` in `tools/build/stylesheets.ts` (KaTeX's, with its fonts inlined and their licences in `tools/font-licences.json`), and the view build's chunk-style check (`styleUrlProblems`) parses each chunk's CSS with `lightningcss` (1.32.0, build-time only, MPL-2.0 unmodified) and fails on any URL except a woff2 `data:` URL in a `@font-face` source, on an `@import`, on any substitution into `image-set()` (`var()`, `env()`, a custom function) and on an `@function` rule, so a chunk loads no file. Versions: input format 1.7, output format 1.7, tool envelopes 1.7 and board document 1.6, bound on 2026-11-07 on main 35383721, each one minor past `main`'s (the board protocol 1.6, the Snapshot data and the view manifest are unchanged).
