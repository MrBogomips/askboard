# As built: `form-widget`

In code since `form-widget`: field checks in the registry (`WidgetType.fieldCheck`, `contract/src/widgets/field-checks.ts`: `FieldCheckFailure`, `requiredFailure`, `fieldCheckMessage`, `fieldCheckProp`, a `switch` with no default over the failure codes, which the view's field errors and `core`'s refusals both read; `widgetFieldCheck` is in `widgets/widget-field-check.ts`, apart from the entries so the registry import makes no cycle): `required` on the five input atoms and the PickField, `minLength` and `pattern` on the TextField (`maxLength` stays an input cap and a fit rule, never a field check), `minItems` and `maxItems` on a multiple PickField, a value that fails a check still fitting the result schema (a malformed one does not), and `false` and `0` holding a value for `required`. Where each runs: `contract` checks the shapes and fits when the ask or update is sent; `core` (`fieldCheckProblem` in `lifecycle/widget-event.ts`, over the answer's sent items at any depth, after `answerRequirementProblem`, for answers only) refuses an answer that fails one, appending, keeping and publishing nothing, but never runs an agent pattern and builds no `RegExp` from item props (a source guard; threat model §3.7); the pattern runs only in the view, in the TextField's chunk, through `textFieldPatternFailure`, which fails a text over `textFieldLimit(props)` before it reaches the pattern. The pattern is held to the safe subset by `patternProblem` (`widgets/shared/pattern.ts`, one pass after a compile with the `u` flag: at most `PATTERN_MAX_CHARS` = 200 code points, no backreference, lookaround, group form but `(?:` and `(?<name>`, repeated group name, nested quantifier or alternation inside a repeated group, at most `PATTERN_MAX_REPEATS` = 3 repetitions, one more without a leading `^`, and a `\p{…}` only for a General_Category value or an ECMAScript 2018 binary property, by `widgets/shared/property-names.ts`), on a field whose text is capped at `PATTERN_TEXT_MAX_CHARS` = 100 code points (a `maxLength` or `minLength` over it is refused), and runs unanchored, one run per keystroke at most, whatever the number of fields, through each field's last outcome and compiled pattern kept in a `WeakMap` keyed by the item's props object (the shell passes the document's own objects, so an ask of 200 patterned fields costs one run per keystroke; an update that replaces the document costs one run per filled field, once per replacement: the board page sends the view the document only when it differs from the last one it sent), and a memo of 64 outcomes, least recently used first, for a caller with no props object (`patternRunCount`, `clearPatternOutcomes`). The PickField (`widgets/pick-field/`, `catalog/pick-field/`): 2 to 50 options, a single pick on AskBoard's own radio group with "Clear" or a multiple pick on one Checkbox per option, never a dropdown, a filter above 10 options held as the component's own state and never in the draft, a result that is an option ID or a list of them (the schema an `if`/`then`/`else`, since the contract compiles in strict mode and refuses a type union and a root combinator), its teaching in the skill (`{{formNote}}`, `SKILL.md` at 6,217 of 9,000 characters, the PickField's line in `references/items.md`). The field block (`shell/field-block.ts`: `fieldBlock`, `holdsBlock`, `answerHint`, with kind `entry`, `check` or `required`; `ComponentFacts.check`, each field chunk's own check of a result) replaces the entry block as the one reader that disables "Answer", "Accept recommended", "Select recommended", "Send and switch" and the Submit bar (the press kind `field-block`), with the hint "Correct {label} first." or the question's `requiredHint`; a required field shows "(required)" and no error while empty. No form library: `@rjsf/core` and `@rjsf/utils` are out of the stack. Chunk sizes that moved (bytes, recorded in `chunk-sizes.json`): `text-field` 8,870 to 17,332 (the contract's checks and the property-name tables), `pick-field` 18,020 (new), `shell` 169,014 to 172,018, `board-page` 910,953 to 931,284, `date-field`, `money-field`, `number-field` and `toggle` by about 700 to 800 each. Browser scenarios: `form-fields.browser.ts`, `pick-field.browser.ts`, `form-session.browser.ts` and `form-snapshot.browser.ts`. Versions: input format 1.11, output format 1.10, tool envelopes 1.11 and board document 1.10, bound on 2026-11-08 on main 90b7009f, each one minor past `main`'s (board protocol 1.7, Snapshot data 1.1 and view manifest 1.1 unchanged).
