# As built: `palettes`

In code since `palettes`: the presentation key `palette` (`PALETTES`, `Palette`; `carta` by default, at user and project level), admitted by the configuration, the board protocol's `setting` and `settings` messages and the Snapshot's presentation, recorded by `presentationNow`, and carried by `ViewPresentation`, `presentationOf` and the opened Snapshot's `snapshotPresentationOf`. The palettes are data: DESIGN.md's `palettes:` holds one whole group per palette besides Carta, which `readDesignTokens`, `checkPalettes` and `paletteCss` turn into `:root[data-palette]` rules (Carta's CSS stays `tokensCss`), and the view build lists each as `chunks/shell-palette-<name>.css` after the shell's own sheet (`paletteStylePath`, `paletteOfStyle`), the board page's sheet carrying them all, `targetOf` and `selectChunks` keeping a Snapshot's own palette only. `resolvePalette`, `applyPalette` and `followPalette` (with `CONTRAST_QUERY`) set `data-palette` on the board page and, from its own media, on the view, Contrasto replacing the chosen palette under the theme's System when the system asks for more contrast; `QuickToggles` holds the Palette row and its note, fed by `PresentationControls.resolvedPalette`; `useColourScheme` (`colourSchemeOf`) is what the Chart re-reads its tokens on.

Beside them: `tools/build/contrast.ts` (`CONTRAST_PAIRS`, `contrastReport`, `roleReport`, `contrastTable`), whose test computes every pair and role rule, prints each one under its minimum and never fails on one (the report does not block), and whose tables DESIGN.md holds; `styles/contrast.css` (Contrasto's 3 px ring and 1.5 px borders on the elements that carry `border`) and `styles/forced-colors.css` (system colours, `forced-color-adjust: none` on the Chart's host, diff marks and the change fill); the browser files `palettes.browser.ts`, `palettes-fit.browser.ts` and `palettes-forced-colors.browser.ts` (Chromium only).

Seams for later changes: a fifth palette is a YAML group, a `PALETTES` value and two strings; a diagram renderer follows DESIGN.md's Diagram theme and re-renders on `useColourScheme`. A 1.5 px border computes as 1 px at a device pixel ratio of 1, so a test reads the matched rule. The Theme popover is `w-[26rem]` so the four names fit.

Versions bound, on `main` ddf90ae8: configuration 1.3 (main 1.2), board protocol 1.13 (main 1.12), Snapshot data 1.4 (main 1.3); the view manifest and the other sets unchanged.
