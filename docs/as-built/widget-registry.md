# As built: `widget-registry`

In code since `widget-registry`: `contract`'s registry of widget types (`WIDGET_TYPES` with the Tree and the Gantt, `widgetTypeOf`, `widgetRegistryProblems`, which also refuses a type named like a composed schema's definition or an inherited object name and a result schema that accepts `null`, `{}`, `[]` or `""`; each entry in `widgets/<type>/widget.ts` holds the props schema and checks, the element shape, the `changes` schema, the optional result schema and checks, the derived declarations and the wording, which moved into the type's folder) from which the question props, the board document and the `fetch` result are composed (`widgets/compose.ts`), and every dispatch point of `contract` and `core` reads, so a widget is added by registering it (`compute` keeps its Tree and Gantt by hand, by design decision 11, and takes a new computing type through `BOARD_SOURCES`); the probe type `PROBE_WIDGET` and `PROBE_TYPES` in the fixtures, which the tests use in place of a third widget. The answer's `results` seam (output format 1.5, tool envelopes 1.5, board protocol 1.6, Snapshot data 1.1): the annotation schema and each type's result schema in the output format, `results` in the `answer` act, the draft record, the board state, the answer event (which a `tooLarge` answer never carries), `fetch` results and the Snapshot's kept answers; `core` checks each result against its type and refuses the whole answer on a fault or when a result holds no leaf value, with `JSON_MAX_DEPTH` (64) bounding a result or derived value and `DRAFT_RECORD_MAX_DEPTH` the draft record that mirrors it. `compute`'s `BOARD_SOURCES`, the table through which a new computing type feeds the board's graph; in `widgets`, the former `graph` folder is now `board-graph` (chunk `board-graph`); in `view`, the port's `register(name, component, facts?)` and `componentFacts` (a type's shape and its notice's name come from its chunk, so the shell imports no registry), `ItemProps.result` and `onResultChange`, a results store beside the draft store that follows the draft's rules, and the build's `widgetChunkProblems`, which fails when a registered type has no component chunk. No shipped widget gives a result yet: the first one that does carries the browser and session scenarios.
