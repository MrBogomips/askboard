# As built: `atoms`

In code since `atoms`: eight registry entries in `contract`, one folder each under `widgets/` (`text`, `value`, `divider`, `text-field`, `number-field`, `money-field`, `date-field`, `toggle`), appended after the Chart in the registry's order, each with its props schema, plain checks, wording, `skill` text and example (and, for the five input atoms, a bare result: a string, a number, `{amount, currency}`, a full-date or a boolean, keyed by item ID in the answer's `results`), with `skills/askboard/` teaching them; `ATOM_TYPES` in the fixtures gives a test the eight through `withWidgetTypes`. The components are one chunk each under `view/src/catalog/<type>/`, with the label, description, field error, echo and hover classes shared in `catalog/fields/`; the NumberField, MoneyField and DateField read their text with AskBoard's own parser and echo (`parseNumber`, `parseAmount`, `parseDate`, no `Intl`), the MoneyField's amount a decimal string checked against the currency's minor units (`MINOR_UNITS`, ISO 4217's full table of non-2 currencies, in `contract`'s `locale/tables.ts`, which also bounds a Value's money amount and a MoneyField's `min` and `max`), the NumberField counting its own step (`stepTolerance`, refusing what the doubles cannot decide), and the DateField drawing react-day-picker 10.0.2 (with date-fns 4.4.0 and @date-fns/tz 1.5.0, pinned exactly) in a non-modal popover, with AskBoard's tables for the caption, weekdays and labels, the first day of the week and local-date conversion at noon, so no `Intl` call and no time-zone shift reach it. Text a field cannot read, or whose value breaks the item's bounds, is an **entry** (`shell/entries.ts`, the draft record's `entries`, at most `ENTRY_MAX_CHARS` = 200 characters per item): held beside the draft's values and results, restored after a reload, counted as unsent work, and it disables the question's "Answer" (and "Send and switch" and the Submit bar) until the user corrects or clears it, so the agent never receives text the user did not mean (NFR-10); `core` keeps entries apart from the log. Markdown goes through `catalog/text/markdown.ts`: markdown-it 15.0.3 (`html: false`, no linkify, nesting at most 20) then DOMPurify 3.4.17 with an exact tag and attribute list, over a source of at most 10,000 code points and HTML of at most 200,000 characters (past it the item shows its source as plain text), controls shown as `\uXXXX`; an image shows as a link to its source; only `http:` and `https:` links are links, sent to the board page as an open-link message (`ViewOpenLink`) whose handler re-checks the URL and that the item holds Markdown in the board document, and the one predicate `isLinkUrl` in `contract` gives the verdict to both layers, so a refused link shows as text. An option's `previewFormat` (`plain` or `markdown`) makes a preview Markdown, loading the `text` chunk only when one opens. The named licence exception is `argparse` (PSF-2.0, the addendum's Licence exceptions line), which markdown-it's command-line tool needs and no shipped chunk contains: `tools/licence-exceptions.json`, read by `check-licences.ts` (a name at its licence only, an unused entry is stale) and enforced by the view build (`exceptedPackageProblems`); DOMPurify's `(MPL-2.0 OR Apache-2.0)` ships both texts, and the MIT texts its Babel helper and entities' `he` code need are embedded through `tools/font-licences.json`. New dependencies in `view`: `markdown-it`, `dompurify` and `react-day-picker`, exact pins. The sets: the input format's option `previewFormat` and the atoms' props, the output format's atoms' results, the tool envelopes' and board document's composed schemas, the board protocol's `entries`. Versions: input format 1.9, output format 1.9, tool envelopes 1.9, board document 1.8 and board protocol 1.7, bound on 2026-11-07 on main 0e151a84, each one minor past `main`'s (the Snapshot data 1.1 and the view manifest 1.1 are unchanged).
