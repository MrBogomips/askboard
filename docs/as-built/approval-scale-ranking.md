# As built: `approval-scale-ranking`

In code since `approval-scale-ranking`: three registry entries in `contract` and `widgets`, one folder each (`approval`, `scale`, `ranking`), each with its props, result schema, checks, wording, `skill` text and component, so the FR-11 widgets that give a result are registered, and `skills/askboard/` teaches them. The Approval answers `approve`, `approve-with-changes` or `reject`, with edits to the question's other widget items counting as changes: plain approval beside edits is refused, and so is approval with changes without a reason (a note of white space only, U+0085 included, is none); the Scale answers a value or a range (a slider, or a rating on Toggle Group), unset until the user acts; the Ranking answers the order of all its elements, from the first move or from "Keep this order", with the agent's initial order counting for nothing. `core` runs each type's `answerProblems` (`WidgetType.result.answerProblems`), where the changes exist, and refuses the whole answer on a fault, appending nothing; `resultHoldsNothing` is bounded and keeps a `Set` of visited objects. In `view`: `ComponentFacts.reason` (the reason gate: "Answer", "Accept recommended", Submit and "Select recommended" all ask for it) and `ComponentFacts.confirmsRevision` (once the agent has received an answer, a revision asks for confirmation: a dialog for one question, a confirmation before Submit replaces several), `BoardContent.questionItems` (a question's widget item IDs, by question, computed once per document), `ComponentFacts.fits` (each result chunk's own check of a result, its shape and then the item's props, so that a draft holds, seeds or keeps only results its items accept: "Start from my previous answer", a restored draft and "Keep mine" drop the rest), the results store's reads and a new `dnd` library chunk (Pragmatic drag and drop 4.0.0, appended to `LIBRARY_CHUNKS`); in `widgets`, the Approval summary (`summarise`, at most 20 lines). A revision keeps the results the user did not change. Versions: input format 1.6, output format 1.6, tool envelopes 1.6 and board document 1.5, bound on 2026-11-07 on main efe92afb, each one minor past `main`'s (the board protocol 1.6, the Snapshot data and the view manifest are unchanged).
