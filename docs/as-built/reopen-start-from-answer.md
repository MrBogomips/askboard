# As built: `reopen-start-from-answer`

In code since `reopen-start-from-answer`: `core` says what an answer's revision shares with the current one (`lifecycle/unchanged.ts`: `unchangedItems`, a `canonicalize` comparison of the question's and each item's props, at any depth, as the board shows them; `BoardModel.unchangedSince`, memoised per pair of revisions and pruned to the question's current one; `QuestionRecord.previousRev`, set by `reopen`), and `answerView` gives the board state's current and previous answers `unchanged`, present only for an answer on an earlier revision and `[]` when the comparison cannot be made, which `board-host`'s `currentOf` and the Snapshot's pass on. In `view`: `unchangedOf(answer, role)` in `shell/question-state.ts` is its one reader (a current answer without the list holds every item unchanged, a previous one none); `fillFrom(question, answer, role, stores)` carries an answer's choice, notes and results and, for each widget item the answer holds unchanged and whose type shows the value (`valueFits`), its value, and returns whether every part was carried; the revision's start (`revise`) seeds the answer's values by the same rule, and what the card shows of the logged answer is gated apart from any draft: `answeredOf` (in `shell/board-content.ts`) gives an item's value only for an item the answer lists as unchanged (`unchangedOf`) and for no question under revision, `answeredResultsOf` gives a result only where its type's `fits` takes it on the item's current props, and `itemResultOf(…, revising)` is the revision gate for results (#107's fix: once a revision has started the card shows the held results alone, so a result the user cleared stays cleared); none of the three fills a draft key; `shell/revising.ts` holds the one predicate `questionRevising` and `createRevisingSnapshot`, the set of questions under revision, computed once per change of its inputs, which the card, `revise` and every item read; `shell/reopen-prefill.ts` (`reopenPrefills`, `prefillReopened`) fills a reopened question once per revision at the end of each update the board page sends, after that update's restore, never on the boot data and never on a closed or locked board, when the board state lists the question itself as unchanged, it holds no work on any revision and a dry run carries every part; the draft record's `prefilled` mark (the work's `QuestionWork`, kept by `restoreDraft`, ignored by `hasAnswerWork` and `hasUnsentWork` when it stands alone, and moved by `moveMarks` to the question's current revision, in the update handler before the view takes the document and in `connectDrafts`' `prune`, when the work holds nothing else and no value, result or entry is held, read over the question at the work's revision as well as the current one through the `revisions` lookup the shell hands to `moveMarks` and `connectDrafts` (`holdsWorkValues`; a revision never seen leaves the work in place, and `prune` forgets a bare work only when the same reader finds nothing), so that `changePending` and `workingQuestion` see no work on an earlier revision and an agent change shows at once with no notice) keeps a reload from filling again over what the user undid; work held only as an entry on an item the agent's change removes is still forgotten without a notice, as on `main`, until `document-review` (PR #115) merges and `holdsWorkValues` and its `dropStaleEntries(…, shownOf)` become one reader; `ReopenedNotice` takes `carried` (`carriedOf`: the mark on the current revision and the previous answer listing the question itself as unchanged) and shows `reopened.carried` or `reopened.notCarried` (two strings in both tables, the Italian texts to review). `Boards.#openers` sends the draft before the state, and the board page's `#onDraft` hands the view the restore only once the socket's state has come (`#stateSeen`), so the first update after a reload or a takeover carries the restore whenever one was held. Derived values follow keep-mine-shown-revision: an answer to a reopened question names its current revision and carries those of the draft it shows. AD-10, AD-20 and FR-6 amended in place. Browser file: `reopen-session.browser.ts` (cases (a) to (j)). Chunk sizes that moved (bytes, in `chunk-sizes.json`): `shell` 187,964 to 192,860, `board-page` 979,729 to 983,560 (the sizes `main` held at ac9f891f to the sizes recorded here). Versions: board protocol 1.9 and Snapshot data 1.3, bound on 2026-11-09 on main ac9f891f, each one minor past `main`'s (board protocol 1.8, Snapshot data 1.2); every other set equals `main`'s (input format 1.12, output format 1.11, tool envelopes 1.12, board document 1.11, view manifest 1.1).
