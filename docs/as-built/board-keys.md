# As built: `board-keys`

In code since `board-keys` (Issue #187): keys of the board's own, outside text fields and widgets, shown and changeable like a widget's. They are `N` and `Shift+N` (next and previous open question), `Mod+Enter` (answer the question in focus; in the follow-up composer, send the follow-up) and `?` (the board's keys panel). Sending all held answers has no key.

- Contract (`packages/contract/src/keys/`): `BOARD_KEYS` and `BOARD_KEY_TABLE` (`board-table.ts`), under the type name `BOARD_KEY_TYPE` (`board`) and the part `BOARD_PART`; `board` is no widget type's name (a test fails on one). `ALL_KEY_TABLES` (`tables.ts`) is the board's table then `REGISTERED_KEY_TABLES`, and `keyOverridesProblems`, `keyExitActions` and the effective keys default to it; `KEY_TABLES_ON_BOARD` still names widget chunks only. `MOD_KEYS` (`check.ts`) admits `Mod+Enter`. A board action in the part `board` refuses the keys a native control takes, as `keys.open` does. No schema, message, draft field or dependency moved, so no version is bound.
- Pure view parts (`packages/view/src/shell/`): `boardKeyScopeOf` and `scopeTargetOf` (`board-key-scope.ts`: none, the question's own controls, or the board; `scopeTargetOf` takes any `Element` as the target, SVG and MathML included), `answerKeyOf`, `answerableOf` and `answerKeyHandling` (`answer-key.ts`), `previousOpenFrom` (`board-view.ts`), `boardKeyActOf` and `useBoardKeyTable` (`use-board-keys.ts`), `sendKeyOf` (`thread-text.ts`, replacing `isSendKey`). `checkboxKeyOf` (`catalog/fields/roving.ts`) flips a box on Enter with no modifier only.
- The listener: `useBoardKeys` is in `board-keys-listener.ts`, not in `use-board-keys.ts` (it is DOM only, one bubbling `keydown` on the view's document). `Board` starts the next-open and previous-open jumps from `shownQuestionOf(document, current)`.
- The card: `question-card.tsx`'s section `onKeyDown` runs `answerKeyHandling` and calls `onAnswer` or announces through `context.status`; `PrimaryButton` (`primary-button.tsx`) carries `data-askboard-primary` and the key hint; `Composer` (`thread-composer.tsx`) sends on `sendKeyOf` with its own key hint; `thread.tsx` puts `data-askboard-thread` on the thread's section, which the scope reads to leave the thread's controls to the board.
- The header and the panel: `HeaderActions` (`header-actions.tsx`: the counts, the jump with its key hint, the "Keys" button), `BoardKeysButton`, `BoardKeysPanelBody` and `useBoardPanel` (`board-keys-panel.tsx`, the panel built from `keys-frame-actions.ts` and `KeysPanelBody`); `panelGroups` has the group `board`. The Keys button shows on every board that has not ended.
- Strings (`strings/`): `keys.action.board.previousOpen`, `keys.action.board.answer`, `keys.action.board.sendFollowUp`, `keys.group.board`, `keys.panel.boardTitle`, `keys.panel.boardNote`, `status.answerBlocked`, `status.answerEmpty`, `status.answerChangePending`; Italian outside report section 4 is marked "(to review)" in EXPERIENCE.md. The next-open action is named by `header.nextOpen`.
- The help skill: `key-actions.md` opens with a "Board keys" table from `BOARD_KEYS`; the list of every action and the examples' check read `[BOARD_KEY_TABLE, ...widgets]`; `configure-keys.md` names the board's own keys and the Ranking; its refused-keys line says "`Mod` with any key but Z, A and Enter".
- Tests: `board-keys.browser.ts` and `answer-key.browser.ts` with `fixtures/board-keys-asks.ts` and `fixtures/answer-key-asks.ts`, listed in `suites.ts`.
- Corrects `keyboard-shortcuts-help.md`: `keyOverridesProblems` and `keyExitActions` default to `ALL_KEY_TABLES`, no longer to `REGISTERED_KEY_TABLES` alone.
- Versions: none bound. No set is widened: the configuration schema bounds `keys` by shape only, and no view-protocol message, draft field or dependency changes.
