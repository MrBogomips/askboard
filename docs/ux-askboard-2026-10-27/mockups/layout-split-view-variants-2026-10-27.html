Why does the second fix touch the queue?

Main agent · Payment retry fix17:43

Fix B moves the re-enqueue into PaymentQueue so that every retry carries the payment's retry key and a second enqueue with the same key is dropped. Fix A only caps the attempts, so a worker that crashes after charging and before acking can still queue the same payment twice. ADR-012 asks for idempotent re-enqueue, which is why fix B touches the queue.
