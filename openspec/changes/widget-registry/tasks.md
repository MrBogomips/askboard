# Tasks

Each task writes its tests first and sees them fail for the right reason before it implements (the repository's TDD rule). "The check" means `GITHUB_TOKEN=$(gh auth token) bun run check`. "Coverage" means at least 80% of lines and functions for every file the task adds or changes, read from `bun test --coverage`'s per-file table. "Unchanged" means an existing test passes with its expected values and texts as they are on the base; a test whose list of widget types now comes from the registry says so in its task's note. Every task that touches answers includes a test that the failing case appends nothing and publishes nothing (NFR-10, AD-10). After each task: `openspec validate --all --strict --no-interactive`, `bun run format` with `git status` showing only the task's files, the check; then tick the box with a note of about five lines (what was built, test counts, deviations) and commit in conventional form with no attribution. Contract versions follow askboard-contract-versioning; appended export blocks and the chunk budget follow askboard-implementation.

Order: group 0 first; groups 1 and 2 (contract) in order, task 1.4 (`compute`) may run beside 1.2 and 1.3 once 1.1 is done; then groups 3 (session side) and 4 (view, widgets, build) in parallel, since they meet only through the contract's sets, types and fixtures, and tasks 4.1 and 4.2 may start as soon as group 1 is done; group 5 last.
