# Proposal

## Why

UJ-2 and UJ-3 end with a Snapshot: the agent saves the board's final state and builds the client deck or the offer from its data and visuals (FR-26, FR-27). Nothing in AskBoard writes one yet. E1 built `assemble` with a Snapshot in mind and left the `snapshot` unit empty; E3 (`ask-lifecycle`) lists four tools and hands the `snapshot` tool and its files to this epic (its open question 1); E4 (`push-delivery`) gives every ask an owner and an origin. E7 now carries a board out of the session: one self-contained HTML file in the project, taken by the agent or by the user, that opens offline, holds no token, can be read by an agent without rendering, and can never be answered.

## What Changes

- **`snapshot`** (new unit, `packages/server/src/snapshot/`): writes a Snapshot into the default Snapshot folder `.askboard/snapshots/` under the session project root, creating `.askboard/`, the folder and `.askboard/.gitignore` when they are missing; names the file `<ask-id>-<UTC timestamp>-<short random>.html` and never overwrites one; builds it with `assemble` from the view build the session process serves, with the licence notices of the inlined code; refuses a folder whose real path leaves the project (AD-14, AD-15).
- **`ask-core`**: a `snapshot` command that gathers, in one step, what a Snapshot holds of an open or closed ask (the current board document, the revisions its events name, the board state with threads, recorded and previous answers and receipts, the ask's origin, every event of the log with the full values `ask-core` keeps for each answer, and the molecule expansion map) and hands it to a new driven port, `SnapshotWriter`; never the draft record, a token or the agent's presence. A discarded ask, or one unknown to the epoch, is `discarded`; an agent's request passes E4's owner check, as `fetch` does (AD-5, AD-10, AD-15, AD-20, AD-21).
- **`mcp-tools`**: the `snapshot` tool, fifth in AD-6's order with the approved definition, in its own appended block; its result names the file's absolute path and the ask's state, never the content; typed `discarded`; the owner's refusal and a write failure as errors (AD-6, FR-26).
- **`board-host`** and the board page: a Snapshot request from the board, for an open or closed ask, answered with the path or the failure; it says whether the board held unsent work, and is never an event (FR-26, AD-15).
- **`view`**: `assemble` builds a Snapshot (the `askboard-data` block, the view policy, the chunks the board uses, no ext-apps `App`, kept diagram renders in place of a renderer chunk, the licence notices last); the view build marks the ext-apps chunk as needed only with a host; the Snapshot control in the bottom action bar and on the Closed banner, with its feedback and the unsent-work note; the Snapshot view: booted from the data block with no host, its top line, read-only, navigable and never answerable (AD-8, AD-9; EXPERIENCE Snapshots).
- **`contract`**: the `snapshot-data` schema set at 1.0, owned by `snapshot`; the `snapshot` request and result envelopes; the board protocol's Snapshot messages; the view manifest's optional `hostOnly` and `keptRender` (1.1); Snapshot constants; fixtures. Every registration is an appended block.
- **Checks**: unit tests first, at 80% per file; browser tests of the board's Snapshot control and of an opened Snapshot from `file://` in Chromium, Firefox and WebKit, offline and with AskBoard stopped; one end-to-end run on the real session process, from ask to an opened Snapshot whose data validates; the conformance suite on Bun and Node 24.
- **Documents**: `spine-update-draft.md` for AD-15 (what the data block holds, its place, the file name, the path), the Structural Seed (the new port), SOLUTION-DESIGN §5.6 and EXPERIENCE (strings, open item 19), applied after the PO's answers. No PRD change.
- **Not in this change:** reading `snapshotFolder` from configuration, the outside-project replacement and the settings row (E8, open question A5); AD-14's creation of `.askboard/` at a session's first ask (open question A6); diagram renders on the board, their store in `board-host` and their message (the Diagram widget's epic, open question B3); the Snapshot looks of widgets not yet built and of references (the widget epics and E5, open question B8); teaching agents to read a Snapshot (the skills epic); it-IT strings (E8).

## Capabilities

### New Capabilities

- `snapshot`: the Snapshot folder, the file's name and its writing without overwrite, the self-contained file built through `assemble`, write failures, Snapshots outliving their ask.

### Modified Capabilities

- `contract`: the `snapshot-data` set, the `snapshot` envelopes, the board protocol's Snapshot messages, the view manifest's host-only and kept-render chunks, Snapshot constants and fixtures.
- `core`: taking a Snapshot, what it holds, the owner check, and that it changes nothing in the ask.
- `mcp-adapter`: five tools, and the `snapshot` tool's results.
- `board-host`: Snapshot requests from the board.
- `view-and-widgets`: assembling a Snapshot, host-only chunks in the view build, the Snapshot control and the Snapshot view.

The `mcp-adapter` delta modifies the tool list as E3 leaves it, so this change is archived after E1's, E3's and E4's.

## Impact

- **Code:** `packages/contract`, `packages/core`, `packages/server` (`snapshot`, `mcp-tools`, `board-host`, the entry point's wiring; `@askboard/view` becomes a dependency, for `@askboard/view/assemble` only, as AD-1 and `tools/check-imports.ts` already allow), `packages/view` (`assemble`, the shell's boot, the bottom action bar, the board page), `tools/build/` (the host-only chunk); `packages/view/chunk-sizes.json` re-recorded.
- **Dependencies:** none new.
- **Other changes:** depends on E3 and E4 (group 0 waits for both on `main` and checks every name borrowed from them); reads tree-widget's port and view document, widget-answers' stored full values and molecules' expansion map, and hands work to the Diagram epic, E5, E8, the widget epics and the skills epic (design, Handed on).
- **CI:** the browser and end-to-end jobs gain the Snapshot cases; no new job.
- **Requirements served:** FR-26; FR-27 except the configured folder (open question A5), which FR-35's settings row shows once E8 reads it; FR-13's single-question board, which keeps "Snapshot"; NFR-4 (no token in the file), NFR-5 (agent content as data in a Snapshot), NFR-6 (licence notices), NFR-7, NFR-9 (offline, no request), NFR-10 (no Snapshot of a discarded ask; no draft); UJ-2 step 5 and UJ-3 step 4.

## Open questions for the PO

Each question records the narrowest choice, which the change proceeds with, and why. An answer that reverses one stops the work at task 0.4 for `/opsx:update`.

### A. The Snapshot FRs and AD-15

1. **What the data block holds.** AD-15 lists the board documents, the log with each answer's full value, and the kept diagram renders. FR-26 also needs the context header (who asked, where, the ask state), every follow-up thread and the postponed marks, and AD-3 keeps replies and recorded answers out of the log, while the board document holds neither. *Default:* the block also holds the board state the live board receives (per question its `rev`, state, current and previous answer, whether recorded, receipt and thread), the ask's origin as E4's `origin` message carries it, and the Snapshot's own record (when, by whom, and whether the board held unsent work). Each answer event carries the full values `ask-core` keeps for it, as widget-answers stores them. AD-15 is amended (spine draft block 1). *Why:* the view renders a Snapshot from the same inputs as a live board (AD-9), and an agent reads what the user saw. *Alternative:* AD-15's list only, with replies and recorded answers made events, an AD-3 change.
2. **Expanded IDs or references** (handed to E7 by widget-answers and molecules). *Default:* each part as `ask-core` holds it: the board document, revisions and board state with expanded IDs (`wbs__tree`), as the view renders them; the events and their full values in reference addressing (`wbs.portal.label`), as `collect` and `fetch` return them; and the expansion map (expanded ID to reference, molecule and version), so a reader can join the two. *Why:* no translation code, and the file agrees with what the agent already received. *Alternative:* translate the documents to references, or leave the map out.
3. **The data block's place.** AD-15 says the block "comes first", then the chunks, their styles, the CSP meta tag and the notices. E1's `assemble`, which also builds the board's srcdoc, writes the charset, the CSP meta tag, then the block, the styles and the scripts. *Default:* keep that order, put the licence notices last, and amend AD-15 to "before every style and script". *Why:* a meta policy governs only what follows it, and the block still starts in the file's first kilobyte. *Alternative:* move the block above the CSP meta tag in both outputs.
4. **The file name and the returned path.** AD-15 gives no timestamp format; FR-26 says "the path". *Default:* `<ask-id>-<YYYYMMDDTHHMMSSZ>-<6 characters from [a-z0-9]>.html`, the basic ISO 8601 form, with no colon (refused on Windows drives under WSL, shown as a slash by macOS Finder); the result gives the file's absolute real path. *Why:* an absolute path is unambiguous for a subagent working in another worktree. *Alternative:* RFC 3339 with colons; a path relative to the project root.
5. **The configured folder** (FR-27's "the user can change it", FR-35). Configuration is E8's. *Default:* E7 writes only into the default `.askboard/snapshots/` under the session project root; E8 adds the `snapshotFolder` key, AD-14's replacement of a folder outside the project, and the settings row. *Alternative:* E7 reads that one key before E8's `Config` port exists.
6. **Creating `.askboard/` and its `.gitignore`** (FR-27's "ignored by git by default", AD-14). AD-14 creates `.askboard/` and every subfolder at a session's first ask, which no epic does yet. *Default:* E7 creates `.askboard/` and `snapshots/` when it writes a Snapshot and they are missing, and writes `.askboard/.gitignore` with AD-14's four lines only when that file does not exist; the first-ask creation stays with E8. *Alternative:* E7 implements AD-14's first-ask creation whole.
7. **A Snapshot the user takes reaches the agent only through the folder** (FR-26). *Default:* no event, no push, nothing in `collect`, and AD-3's event list unchanged. *Why:* FR-26 asks only that the agent can find it in the folder. *Alternative:* a Snapshot event (AD-3 and an output-format minor), which would tell the agent at once.

### B. Implementation choices

1. **How a request reaches `snapshot`.** `board-host` and `mcp-tools` may not import another adapter (AD-1). *Default:* an `ask-core` command `snapshot`, with a driven port `SnapshotWriter` that `snapshot` implements and the entry point wires; the Structural Seed's port list gains it (spine draft block 4). *Why:* one gathering and one owner check for both callers. *Alternative:* a `board-host` port wired straight to `snapshot`, with the gathering done twice.
2. **Leaving ext-apps out** (AD-9). The shell imports `App` when it loads, so its chunk needs the ext-apps chunk. *Default:* the view manifest's optional `hostOnly: true` on the ext-apps chunk; the shell reaches `App` through the shared-module registry only when it has a parent; `assemble` adds host-only chunks to a board's srcdoc and leaves them out of a Snapshot. *Alternative:* a separate channel chunk kind.
3. **Kept diagram renders before the Diagram widget.** *Default:* the `assemble` seam only: the data block's optional `renders` (per item, its `rev` and its light and dark SVG text), and the view manifest's optional `keptRender`, naming the chunk that shows them (the renderer spike's `diagram-svg`); unit tests over a fixture manifest with a probe renderer chunk and a probe kept-render chunk. No render store, view message, gathering or browser test of a render: the Diagram epic adds them through an `ask-core` port. *Alternative:* nothing for diagrams in E7.
4. **The licence notices' form.** *Default:* one `<script type="application/json" id="askboard-licences">` after the scripts, listing `{package, version, licence, text}` for the inlined chunks, with `<` escaped. *Why:* readable without rendering, like the data block; an HTML comment cannot hold `--`. *Alternative:* the texts in a `<template>` element.
5. **The unsent-work note.** EXPERIENCE has the board say so "before taking it" and records no confirmation. *Default:* the note shows as the Snapshot is taken, with no confirmation, and the file's top line adds "· your unsent work is not included" (provisional). *Alternative:* a confirmation step.
6. **"By whom" in the top line.** *Default:* "by the agent", or "by <who>" for the user's, with `who` declared as for answers (FR-19); the time in the viewer's time zone, in the ask's locale (en-US until E8). Strings provisional. *Alternative:* "by the user".
7. **Whether the board shows a Snapshot the agent took** (EXPERIENCE open item 19). *Default:* no. *Why:* nothing records it on the board, and A7 keeps Snapshots out of the log.
8. **Widgets in a Snapshot.** *Default:* every item renders with `disabled: true`, as an answered item does, so the Tree keeps expand and collapse; no port field. The Snapshot looks DESIGN.md gives widgets (the lone chosen decision, a Switch as "on" or "off", change highlights) and FILE references belong to the widget epics and E5, which add a flag to the port if they need one. *Alternative:* a `snapshot` flag on `ItemProps` now.
9. **A board request across a drop.** *Default:* the control is disabled while the connection is lost; a request carries a `requestId` that the reply echoes and is never resent after a reconnect; one lost to a drop reports failure, naming the folder. *Why:* a resent request writes a second file, and a Snapshot changes nothing in the ask. *Alternative:* E3's action IDs, with `ask-core` remembering each request's path.
10. **Writing without overwriting.** *Default:* a dot-prefixed `.partial` file created exclusively, hard-linked to the final name (the link fails if the name exists; up to five names are tried, each with a new suffix), then removed; where the file system refuses hard links, the final name created exclusively and written in place. *Why:* an agent scanning the folder never sees a half-written Snapshot under its final name. *Alternative:* exclusive creation of the final name only.
11. **The Theme control.** *Default:* if the context header's quick toggles (E8) are not on `main`, E7 builds the Snapshot's Theme control (System, Light, Dark) in the header, applied locally and saved nowhere. *Alternative:* none until E8.
12. **The view build `snapshot` uses.** *Default:* the entry point hands `snapshot` the view build that `board-host` loaded, through a port `snapshot` declares, plus the build's folder for the licence texts. *Why:* the Snapshot inlines the same chunks the board runs. *Alternative:* `snapshot` loads and checks the build itself.
