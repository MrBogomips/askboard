# Tasks

Each task writes its tests first and verifies that they fail for the right reason before it implements (the repository's TDD rule). "Check passes" means `bun run check` (typecheck, lint, `bun test` with at least 80% coverage per file, imports), with `GITHUB_TOKEN=$(gh auth token)` for the licence step. "Browser tests pass" means `packages/view/test/browser/` in Chromium, Firefox and WebKit, with no CSP violation from the view, the board page, an opened Snapshot or the console. Every task that touches what a Snapshot holds includes a test that it holds no draft, no board link and no token (AD-15, NFR-4, NFR-10).

Scope and order: group 0 waits for E3 and E4 and checks what E7 borrows; groups 1 to 6 build the session side from the contract outwards; groups 7 and 8 the board's control and the Snapshot view; group 9 the end-to-end and conformance runs; group 10 the integration checks. Groups 2 and 3 may run in parallel once group 1 is done. The files shared with E3, E4 and the widget changes are in design.md, Merge points. Every task that uses a name of E4's (design decision 1: its row and its dispatch tables) waits for push-delivery's merge to `main` (task 0.1), and says so.
