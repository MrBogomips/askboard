# Proposal

## Why

A question on the board still arrives without the context it refers to: the approved UJ-1 ask already points at `docs/adr/0012-payment-retries.md#Decision`, and no unit can read it, show it or open it. E5, the context epic, puts that context beside the question (PRD §4.2): excerpts by pointer or written by the agent (FR-8), references the user opens in one click, project files in a reading panel inside the board with "Open in editor" (FR-9), and images by pointer (AD-12). Together with E3's follow-ups it meets AXFX FR-37 ("Each question carries enough context, with links to reference material, for the person to understand it and act on it"). Pointers make AskBoard read files on the user's machine, so confinement to the ask's root and the source view's isolation are the core of this change (NFR-3, NFR-4, NFR-5, AD-8, AD-11, AD-12).

## What Changes

- **`contract`**, the next minor of the input format, output format, board document and board protocol (design decision 2):
  - three item types inside a question's `items`: `excerpt` (`pointer` or `text`, optional `title`), `reference` (`pointer` or an `http:` or `https:` `url`, optional `title`) and `image` (`pointer` and required `alt`); no image data and no image URL in tool input;
  - the pointer grammar of the Consistency Conventions as one parsing function: a root-relative path, `#`, then `L<start>-L<end>`, a heading or an ID;
  - the board document's resolved context: each pointer excerpt with its status, reason, source text, media type and line range; each image with its status, bytes and media type; each reference with its kind (`file`, `github` or `web`, shown as FILE, GITHUB, WEB) and status;
  - the warning `unresolved-pointer` naming the item, the pointer and the reason (AD-6);
  - the source view route `/s/<askId>/<itemId>`, its responses and its policy; four board-protocol messages (opening a source, its state, "Open in editor", its outcome); the context placement of a question in the draft record; limits as shared constants.
- **`excerpts`** (`packages/server/src/excerpts/`, the unit's first code): the `SourceFiles` adapter that resolves a pointer read-only and only inside the ask's root. It refuses `..`, absolute paths and paths that leave the root through a symlink, compares real paths exactly, opens without following the last link and without blocking, and reads only regular files within the limits. It finds the anchor, decodes text and recognises images by their content.
- **`ask-core`**: resolves every pointer of a revision through that port when an `ask` or `update` is sent and stores the result with the revision; builds the board document from it; reports unresolved pointers as warnings; gives `board-host` a source's current state and the target for "Open in editor", resolved and confined again at that moment. The ask's root is the one AD-12 names: the owning agent's worktree from E4's origin, else the real path of `CLAUDE_PROJECT_DIR`, and with neither every pointer is unresolved.
- **`mcp-tools`**: `ask` and `update` results carry the `unresolved-pointer` warnings; `fetch` omits excerpt text and image bytes (AD-6).
- **`board-host`**: the token-gated source view, a page built from text with `nosniff` and its own CSP, which only a board page of its origin may frame; the board page's policy gains `frame-src 'self'` (AD-8); the editor launch, started only by a click on the board page, with an argument vector, the file's absolute real path confined again at the click and an integer line.
- **`view`**: the context column beside the question, split when at least one excerpt resolved (FR-13), with the per-question "Beside | Inline" control kept in the draft record; the Excerpt, Reference and Image components, unresolved states included, all rendered as text or `blob:` images; references leave the view as an open-link message naming only the item. The board page gains the reading panel, a side sheet that frames the source view with an empty `sandbox`, and opens web references in a new tab with `noopener` and `noreferrer`.
- **Tests**, each written first: confinement attacks on real temporary folders (`..`, absolute paths, symlinks out of the root, the real path's prefix, case and Unicode forms on macOS, FIFOs, swaps between send and click); the source view's headers and escaping; browser scenarios in Chromium, Firefox and WebKit; an end-to-end scenario on the real session process; and a security review.
- **Documents**: `spine-update-draft.md` (AD-8, AD-11, the Consistency Conventions, the Structural Seed, the Deferred table, and SOLUTION-DESIGN §4.5 and §12) and `ux-update-draft.md` (EXPERIENCE: Display atoms, Context column, Reading panel states, Open Items 11 and 20). Each block is applied only after the PO's answer to the question it serves. No PRD change.
- **Not in this change** (each an open question below): the excerpt per work package of the WBS with PERT (A12); Diff review's patch files (B16); Markdown rendering and syntax highlighting of a source (A7, A8); the `editor` and `contextPlacement` settings themselves, which come with configuration (E8; A3, A13); Italian strings (E8); the Snapshot (E7), which carries E5's board-document fields with no work of its own.

## Capabilities

### New Capabilities

None: the `excerpts` unit belongs to the board-host capability (SOLUTION-DESIGN §3.1), and every other behaviour to a capability E1 created.

### Modified Capabilities

- `contract`: context items in the input format, the pointer grammar, the board document's resolved context, the `unresolved-pointer` warning, the source view route and policy, the board-protocol messages for the reading panel and the editor, context placement in the draft record, the limits.
- `core`: resolution at ask and update time through the `SourceFiles` port, per revision; the ask's root; warnings; a source's state and the editor target for `board-host`.
- `mcp-adapter`: warnings in `ask` and `update` results; `fetch` without excerpt text or image bytes.
- `board-host`: pointer confinement and reading in `excerpts`; the source view; the board page's `frame-src 'self'`; the editor launch; the composition of the session process.
- `view-and-widgets`: the split question and the context column, the three components, context placement, the reading panel and opening references.

The deltas build on requirements that E1, `ask-lifecycle` (E3), `push-delivery` (E4) and `widget-answers` add, so this change is archived only after those.

## Open questions for the PO

The PO is away and asked every session to keep working. Each question records the narrowest choice that still meets FR-8 and FR-9, which the change proceeds with, and why. An answer that reverses one stops the work at task 0.3 for `/opsx:update`.

### A. The PRD, the ADs and the UX documents

1. **The source view's token travels in its URL** (AD-11). An iframe's navigation cannot carry a request header, and AD-8 has the reading panel frame the token-gated source view by URL. *Default:* the frame loads `/s/<askId>/<itemId>?t=<token>`, the token in the query as on the board link; the source view sends no referrer, loads nothing and runs no script, so the URL cannot leak through it. AD-11's "The token travels in the page URL" is amended to name both pages AskBoard serves on the board origin (spine draft block 2). *Alternative:* a short-lived ticket bound to one item, issued over the board protocol, so the board token stays out of every URL but the link; it adds state and a message pair.
2. **The reading panel's frame and the source view's policy** (AD-8). AD-8 sandboxes the view's iframe but says nothing of this frame. *Default:* the frame carries an empty `sandbox` attribute (no flag: no script, an opaque origin, no popups, no top navigation, no forms) and `referrerpolicy="no-referrer"`. The source view's policy is AD-8's four directives plus `base-uri 'none'` and `form-action 'none'`, which only narrow it (spine draft block 1). *Alternative:* no `sandbox`, relying on the policy's absence of script.
3. **"Open in editor" before configuration** (FR-9, FR-35, AD-14; EXPERIENCE Open Items 20). Configuration and its `Config` port come with E8 (E1 open question 7). *Default:* E5 builds and tests the whole launch path with the command supplied by the session process's composition; until E8 reads the user configuration's `editor`, none is set, and the reading panel shows "Open in editor" disabled with "No editor set: `editor` in ~/.config/askboard/config.json" (provisional). FR-9's second consequence holds end to end once E8 merges. *Alternative:* E5 reads that one key from the user configuration itself, ahead of E8's port.
4. **Where the file and line sit in the editor command** (spine Deferred, "Implementation"; SOLUTION-DESIGN §12). *Default:* `editor` is an argument vector, a JSON array of strings whose first element is the program. AskBoard replaces exactly `{file}` and `{line}` wherever they occur inside an argument, and nothing else; with no `{file}`, the path is appended as the last argument. So `["code", "--goto", "{file}:{line}"]`, `["vim", "+{line}", "{file}"]` and `["idea", "--line", "{line}", "{file}"]` all work, with no shell. E8's configuration schema adopts the form (spine draft block 3). *Alternative:* one string with a fixed `{file}:{line}` suffix, which several editors do not read.
5. **What a heading or an ID matches** (FR-8; Consistency Conventions, "Excerpts and media"). FR-8 names "an ID" without defining it, and AskBoard never searches (FR-9, Out of Scope). *Default:* an anchor that is not `L<start>-L<end>` matches, in a Markdown file (`.md`, `.markdown`), the first ATX heading outside fenced code whose text equals the anchor; failing that, the first such heading that holds the anchor as a whole word, as in `#### FR-8: Excerpts beside the question` or `### AD-12 — …`. The excerpt is that heading's section, up to the next heading of the same or a higher level. In any other file only line ranges resolve (spine draft block 4). *Alternative:* an ID anywhere in any file, with the excerpt its paragraph.
6. **The pointer grammar's edges** (Consistency Conventions). *Default:* the first `#` ends the path; a path with an empty, `.` or `..` segment, a leading `/`, a backslash or a control character is unresolved; `L<n>` alone is not a line range; an excerpt's pointer needs an anchor, a reference's may omit it (the file opens at its top) and an image's has none. Each case reaches the agent as a warning naming the reason (spine draft block 4). *Alternative:* normalise `./` and accept `L<n>` as a one-line range.
7. **Agent-written excerpts are source text, and count for the split** (FR-8, FR-13; EXPERIENCE Excerpt and Display atoms). EXPERIENCE's Excerpt row says an excerpt "always shows as source text with its line numbers", while its Display atoms row sends agent-written excerpts through the Markdown sanitizer. Rendering Markdown needs markdown-it and its licence exception (renderer row 20). *Default:* every excerpt shows as source text with line numbers, the agent's included, and an agent-written excerpt counts as resolved, so its question splits. The Display atoms row loses the phrase (UX draft block 1). *Alternative:* render agent-written excerpts as sanitized Markdown, which brings markdown-it into this change.
8. **No syntax highlighting yet** (DESIGN, Syntax highlighting: "Highlighting is on in the first version"). Highlighting a source view needs Shiki's grammars on the session process, about 8 MB, since the source view runs no script. *Default:* excerpts and the source view show plain text with line numbers. Highlighting comes with the Diff review epic, which adopts Shiki and its fixed grammar list (renderer row 12), and then extends to source views. DESIGN is unchanged, since the first version as a whole still ships it. *Alternative:* adopt Shiki here, server side.
9. **References without an excerpt** (EXPERIENCE Open Items 11). *Default:* a question whose context has no resolved excerpt does not split. Its references, and its unresolved pointers, show inline under the question text, under the "Excerpt and references" label, with no "Beside | Inline" control (UX draft block 2). *Alternative:* split for references alone.
10. **Reference kinds and labels** (FR-9; EXPERIENCE Voice and Tone, which names "FILE" and "GITHUB"). *Default:* FILE for a pointer; GITHUB for a URL on `github.com` or `gist.github.com`; WEB, a new provisional label, for every other `http:` or `https:` URL, Atlassian's included. Each opens in the user's browser as FR-9 asks, and AskBoard fetches none (NFR-9). *Alternative:* an ATLASSIAN label for `*.atlassian.net`.
11. **Large files and long excerpts** (EXPERIENCE State Patterns, "Very large file: not recorded"). *Default:* the source view shows a file of up to 2 MiB and 20,000 lines. A larger file shows "This file is too large to show here" with its path and size, and "Open in editor" stays enabled. An excerpt longer than 1,000 lines or 64 KiB is unresolved, with reason `too-large`, so the agent narrows it (UX draft block 3). *Alternative:* cut both at the cap and say so.
12. **The excerpt per work package** (FR-11, FR-15; the molecules change's open question 10). Showing it needs a row-detail field in the Tree, `wbs-pert` 1.1.0 filling it, and E5's resolution; none of the three changes it touches has merged. *Default:* E5 delivers the resolution port and the board-document excerpt shape, and a follow-up after `tree-widget`, `molecules` and `widget-answers` merge adds the leaf's chevron and row detail. *Alternative:* E5 waits for all three and builds it.
13. **The default context placement** (FR-13, FR-35; EXPERIENCE Preferences and Settings). The board-wide `contextPlacement` is a setting the board writes (AD-14), which E8 brings. *Default:* E5 builds the per-question "Beside | Inline" control, kept in the draft record as E3 handed on, and every board starts from "beside" until E8. *Alternative:* E5 also writes the setting, ahead of E8's `Config` port.
14. **Missing strings** (EXPERIENCE Open Items 5). *Default:* provisional English strings: "Unresolved" with the pointer, for an excerpt and an image; "This file is not available" with its path, for a missing file and one outside the root; "This file cannot be shown as text"; "This file is too large to show here"; "No editor set: …"; "Could not start the editor"; "WEB". Italian comes with E8 (UX draft block 4). *Alternative:* none.

### B. Implementation choices

1. **How `board-host` reaches a file.** AD-1 lets `board-host` import only `ask-core` and `contract`. *Default:* the `SourceFiles` port lives in `ask-core`. `excerpts` implements it and the entry point wires it, so `ask-core` resolves at send time and answers `board-host`'s requests for a source's state and the editor target with the ask's root it alone holds (AD-5: "`excerpts` … read it from `ask-core` only"). The Structural Seed's port list gains it (spine draft block 5). *Alternative:* a `board-host` dependency wired straight to `excerpts`, with the root passed in.
2. **The root without `CLAUDE_PROJECT_DIR`.** E4's session process falls back to its working directory when the variable is unset, while AD-12 says pointers then resolve as unresolved. *Default:* the composition passes `excerpts` the real path of `CLAUDE_PROJECT_DIR` or nothing; with nothing, every pointer is unresolved with reason `no-root`, whatever the ask's origin. Otherwise the root is the origin's `root` when the ask has one, else the project root, made real again at each read.
3. **How confinement is checked.** *Default:* the syntactic refusals of A6 first, touching nothing on disk. Then the real path of the root and of the candidate, with the candidate inside the root only when it starts with the root's real path plus `/`, compared exactly, with no case folding. The file is opened with `O_NOFOLLOW | O_NONBLOCK`, `fstat` must show a regular file, and its device and inode must match the real path's, so a FIFO cannot hang the session process and a swap between the check and the open is refused. A symlink inside the root that stays inside is followed. *Alternative:* refuse every symlink.
4. **Limits.** *Default:* pointer 1,024 characters; title 256; alt text 1,000; URL 2,048; a file searched for an anchor at most 4 MiB; an excerpt at most 1,000 lines and 64 KiB; an image at most 4 MiB, and 16 MiB of images per ask; the source view at most 2 MiB and 20,000 lines; at most 8 reads at once; a send's resolution bounded at 5 s, after which any pointer still being read is unresolved with reason `timeout`. All are `contract` constants.
5. **Text.** *Default:* UTF-8 with a BOM dropped; a NUL byte or invalid UTF-8 makes a file `not-text`. Lines split on LF, CRLF and CR. The media type is `text/markdown` for `.md` and `.markdown` and `text/plain` otherwise; it decides only wrapping (DESIGN, Excerpt). Bidirectional control characters show as visible `⟨U+202E⟩` markers in excerpts and the source view, so code cannot read differently from what runs.
6. **Images.** *Default:* recognised by their first bytes, never by extension: PNG, JPEG, GIF and WebP. SVG and anything else is unresolved with reason `not-image`. The view shows the bytes only through a `blob:` URL it revokes on unmount.
7. **Request checks.** *Default:* an excerpt has exactly one of `pointer` and `text`, and a reference exactly one of `pointer` and `url`, each checked in code like E1's other checks. A `url` must be absolute `http:` or `https:` with a host and no user name or password. These are request errors the agent must fix (AD-6). Every pointer problem is a warning, never an error, since FR-8 says an unresolved pointer never blocks the board.
8. **Board-document shapes.** *Default:* the resolved fields sit in each item's `props` in the board document: an excerpt `{pointer?, text?, title?, status?, reason?, mediaType?, lines?}`, an image `{pointer, alt, status, reason?, mediaType?, bytes?}` with `bytes` in base64, a reference `{pointer?, url?, title?, kind, status?, reason?, lines?}`. `ask-core` keeps each revision's resolution beside E3's `revs` and prunes them together.
9. **The warning's shape.** *Default:* `{code: "unresolved-pointer", itemId, pointer, reason, message}`, with `itemId` as `widget-answers`' `formula` warning names it. The reasons are `no-root`, `invalid-pointer`, `outside-root`, `not-found`, `not-a-file`, `anchor-not-found`, `not-text`, `not-image`, `too-large` and `timeout`.
10. **Version numbers and `items`.** *Default:* each set takes the next minor after what `main` holds at group 0. If `widget-answers` has merged, E5 appends `excerpt`, `reference` and `image` to its item discriminator. If not, E5 introduces the question's `items` with these three types, and `widget-answers` appends its own on its rebase. `update`'s `warnings` is added by whichever merges first.
11. **Board-protocol messages.** *Default:* page to host `open-source {itemId}` and `open-editor {itemId}`; host to page `source-state {itemId, status, changed?, line?, editor}` and `editor-outcome {itemId, outcome}`. They are added by E3's four appended steps, and the draft record's question takes `context: "beside" | "inline"`, which never counts as unsent work.
12. **One view message for opening.** *Default:* `askboard.view.open-reference {itemId, inset}` serves a FILE reference, a web reference and an excerpt's "Open in reading panel". The board page reads the URL or pointer from the board document it holds, never from the message, and opens a URL only if it is `http:` or `https:` and belongs to a reference of that document. `inset` gives the view's header and bottom bar heights, so the panel sits between them (DESIGN, Reading panel).
13. **The source view's scheme.** *Default:* the frame's URL adds `scheme=light|dark`, which the board page takes from the theme it sends the view. A missing or unknown value follows `prefers-color-scheme`.
14. **One chunk.** *Default:* one component chunk, `context`, registers `excerpt`, `reference` and `image`, so a board with context loads one chunk. *Alternative:* a chunk each.
15. **The Snapshot look.** E7 hands the FILE reference's Snapshot look to E5. *Default:* the components read whether the view has a parent host from the shell, not from an `ItemProps` field. With no host, a FILE reference shows its path and anchor as text, "not available in a Snapshot", the excerpt's "Open in reading panel" is hidden, and a web reference is a link with `target="_blank"` and `rel="noopener noreferrer"`. If E7 lands first, E5 reads its signal; otherwise E7 reuses E5's.
16. **Diff review's patch files and Markdown rendering stay out.** *Default:* `SourceFiles`' confined read is what Diff review will call for its patch files and the paths they name (AD-12); parsing, applying and diffing come with that widget. Markdown rendering comes with the Text atom.
17. **The editor launch.** *Default:* `spawn` with `shell: false`, `detached`, `stdio: "ignore"` and `unref`; the line comes from the anchor resolved again at the click, else the board document's line range, else 1; at most one launch per ask per second. The outcome (`opened`, `no-editor`, `unavailable`, `failed`, `busy`) returns to the board page, and diagnostics never print the command's arguments.
18. **"Changed since the agent asked" only on excerpts.** *Default:* only an excerpt keeps text to compare; a reference opens the current file with no chip.
19. **Layout in a split card.** *Default:* the context column holds excerpts, then references, each in item order. Every other item, images included, takes the widget slot in item order and spans the full card width below both columns, which is right for every widget built so far (DESIGN, Wide widgets). The first narrow widget brings the question-column placement.
