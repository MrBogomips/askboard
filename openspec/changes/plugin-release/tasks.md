# Tasks

Each task writes its tests first and sees them fail for the right reason before it implements. "The check" means `GITHUB_TOKEN=$(gh auth token) bun run check`. "Coverage" means at least 80% of lines and functions for every TypeScript file the task adds or changes, read from `bun test --coverage`. After each task: `npx --yes @fission-ai/openspec@1.15.0 validate --all --strict --no-interactive`, `bun run format`, and `git status` showing only the task's files. Live Claude Code runs use an isolated configuration (`CLAUDE_CONFIG_DIR=<scratch>/cc-config`) and a throwaway project, never the user's configuration (checksums of `~/.claude/settings.json` before and after in the note). Tests of `scripts/askboard` put shim `node` executables first on `PATH` in a temporary folder; they never depend on the machine's Node beyond the real run of the bundle.

Order: group 0 first. Group 1: tasks 1.1 and 1.2 in parallel, then 1.3 and 1.4. Task 2.1 may start beside group 1 once group 0 is done; 2.2 to 2.4 follow group 1. Group 3 follows group 2. Group 4 may start after task 2.3 (the refusal's form is then settled), beside group 3. Group 5 last.
