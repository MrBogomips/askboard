# Tasks

Each task writes its tests first and sees them fail for the right reason before it implements (the repository's TDD rule). "The check" means `GITHUB_TOKEN=$(gh auth token) bun run check`. "Coverage" means at least 80% of lines and functions for every source file the task changes, read from `bun test --coverage`'s per-file table. "Browser files" means the named files run with `bun packages/view/test/browser/run.ts --engines chromium,webkit --target session-process`, under the browser lock. No test added or kept may read KaTeX's script, name an internal KaTeX function, pin KaTeX's version, or match the wording of KaTeX's messages (design decision 4).

Order: group 0 first, then group 1 (`contract`, at high effort), then group 2, then group 3; task 3.2 touches other files and may run any time after task 0.1, in parallel with groups 1 and 2. Group 4 last.
