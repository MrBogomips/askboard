# Tasks

Each task writes its tests first and sees them fail for the right reason before implementing. Terms used below:

- **"The check"** means `bun run build && GITHUB_TOKEN=$(gh auth token) bun run check`.
- **"Coverage"** means at least 80% of lines and functions for every file the task adds or changes under `bun test --coverage`. Browser files are not counted, since `bun run test` does not run them.
- **"Browser run"** means `bun packages/view/test/browser/run.ts --no-build --target session-process` after `bun run build`, with the options the task names. Run one browser run at a time on the machine: other worktrees run theirs too.
- **"Decision n"** and **"Dn"** refer to design.md. The requirement cited by name is in this change's delta spec.
- Commit bodies say `Refs #171` (and `Refs #146` for group 3).

**Order.** Group 0 comes first, then group 1. Groups 2, 3 and 4 then run in parallel, with disjoint files:

- Group 2 edits only `run.ts`, the new `run-options.ts`, `run-plan.ts`, `harness/runtime-dir.ts` and their tests, `isolated()` in `harness/session-process.ts`, `timings/`, and the `test:e2e` and `test:e2e:smoke` lines of `package.json`.
- Group 3 edits only `harness/perf.ts`, `harness/perf-files.test.ts`, the four perf files, the new `document-review-cost.browser.ts`, `latex.browser.ts`'s timed test, `document-review.browser.ts`'s timing block (`:1118-1235`) and the manifest's `perf` flags and `document-review-cost` entry.
- Group 4 edits only `harness/probes.ts`, `harness/probes.test.ts`, `harness/board-test.ts`, `harness/tree-steps.ts` and the other browser files. Task 4.5 waits for task 3.3, because both touch `latex.browser.ts`, and task 4.3 waits for task 3.4, because both touch `document-review.browser.ts`.

Group 5 follows group 2; #171 plan item 1 has merged (#173, design.md M1), so no task waits for another change.
