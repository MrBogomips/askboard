# Tasks

Each task writes its tests first and sees them fail for the right reason before it implements (the repository's TDD rule). "The check" means `GITHUB_TOKEN=$(gh auth token) bun run check` (typecheck, lint, `bun test` with coverage, imports, licences). "Coverage" means at least 80% of lines and functions for every file the task adds or changes, read from `bun test --coverage`'s per-file table, not only the total. "The browser suite" means `bun packages/view/test/browser/run.ts --engines chromium,firefox,webkit --target session-process`, with no CSP violation from the view, the board page or the console. Every task that touches answers, revisions or epochs includes a test that the failing case appends nothing and reports nothing the user did not send (NFR-10, AD-10). After each task: `openspec validate --all --strict --no-interactive`, `bun run format` with `git status` showing only the task's files, the check, and the browser suite when the task touches `packages/view`, `packages/widgets` or `tools/build/`; then tick the box with a `  - Note:` (what was built, the choices made, the evidence) and commit in conventional form with no attribution.

Scope and order: group 0 sets the base; group 1 the contract, which every other group reads; groups 2 to 4 the session side from the core outwards; group 5 the board page and the view; group 6 the records and the end-to-end runs. Groups 2 to 4 and group 5 may run in parallel once group 1 is done, since they meet only through the contract's sets, fixtures and transcripts.
