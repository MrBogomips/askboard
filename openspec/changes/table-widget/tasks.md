# Tasks

Each task writes its tests first and sees them fail for the right reason before it implements (the repository's TDD rule). "The check" means `bun run build && GITHUB_TOKEN=$(gh auth token) bun run check` (the build first: the board page's validators and the chunks are generated). "Coverage" means at least 80% of lines and functions for every file the task adds or changes, read from `bun test --coverage`'s per-file table. "Browser files" means the named files run with `bun packages/view/test/browser/run.ts`, the target the task names, at DESIGN's 1,280-pixel floor, in Chromium and WebKit; Firefox runs only in CI, through a dispatch of `browser.yml` named in the note. Browser runs take the cross-session lock in the same command, in the background or with the maximum tool timeout (600000 ms): `L=/Users/mr/git/MrBogomips/askboard/.git/askboard-browser.lock; mkdir "$L" && echo $$ > "$L/pid" && trap 'rm -f "$L/pid"; rmdir "$L"' EXIT INT TERM HUP && bun run build && bun packages/view/test/browser/run.ts …`; when `mkdir` fails, wait and retry: the lock is stale only when `kill -0 $(cat "$L/pid")` fails. "The Table of roles" is the fixture of the contract spec's first scenario (`fixtures/table.ts`, task 1.3); "the worst form" is design decision 13's, from the same module. "Nested" in a test means inside a Group inside a Tabs. A timing is taken cold (a fresh process or page), on the worst form, and its figures go in the note. Every task that touches answers includes a test that the failing case appends nothing and publishes nothing (NFR-10, AD-10). Every element that shows agent or user text gets a wrap class, checked with 200 characters and no space. A prototype name (`__proto__`, `constructor`, `toString`) is tested wherever agent or user text becomes a key or an ID: row IDs, column fields, item IDs, cell keys. A refusal reaches the user (beside the toolbar, in the live region or as a field error) or the agent (a problem or a warning), never only the console. Every string a component shows goes through the view's tables in en-US and it-IT (askboard-implementation, i18n), with the texts of `ux-update-draft.md` block 1. After each task: `openspec validate --all --strict --no-interactive`, `bun run format` with `git status` showing only the task's files, the check; then tick the box with a note of about five lines (what was built, test counts, deviations) and commit in conventional form with no attribution, one commit per task. Contract versions follow askboard-contract-versioning (labels until task 8.2); appended export blocks and the chunk budget follow askboard-implementation.

Order: group 0 first, then group 1 (`contract`, at high effort). Groups 2 (`compute`, at high effort) and 4 (`view`) then run in parallel: group 2 edits only `packages/compute/` and its tests, and `tools/table-timing.ts`; group 4 only `packages/view/src/catalog/{number,money,date}-field/read.ts`, `catalog/port.ts`, `shell/`, `board-page/unsent-work.ts`, `strings/` and `view`'s tests. Group 3 (`core`, at high effort) follows group 2; group 5 (`widgets`' pure modules) follows groups 2 and 4; groups 3 and 5 run in parallel: group 3 edits only `packages/core/` and its tests, group 5 only `packages/widgets/src/table/model/`, `packages/widgets/src/board-graph/recalc.ts` and their tests. None of groups 2 to 5 edits `contract`'s export blocks. Group 6 follows groups 3 and 5; group 7 follows group 6; group 8 last.
