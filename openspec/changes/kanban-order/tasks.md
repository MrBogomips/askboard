# Tasks

Each task writes its tests first and sees them fail for the right reason before it implements (the repository's TDD rule), and ends with a note of about five lines: what was built, the test counts, the deviations, `Refs #79`. Terms:

- "The check" is `GITHUB_TOKEN=$(gh auth token) bun run check`.
- "Coverage" is at least 80% of lines and functions for every source file the task changes, from `bun test --coverage`'s per-file table.
- "Browser files" are the named files run with `bun packages/view/test/browser/run.ts --engines chromium,webkit --target session-process -- <files>` after `bun run build`, under the browser lock.

Order: group 0, then group 1. Groups 2 and 3 may run in parallel after group 1: group 2 touches only `packages/core/test` and `packages/server/test/board-host`, group 3 only `packages/widgets/src/kanban`, `packages/widgets/src/approval` tests, `packages/view/src/strings` and `packages/view/test/browser`, except task 3.6 (added on 2026-11-09, after group 2 closed), which also touches `packages/contract` (the grouped diff, its tests and fixtures) and the core and board-host tests whose literal changes move with them, at high effort. Group 4 waits for both; group 5 is last. Inside a group, tasks run in order and the checkpoint closes it over the whole group's range; in group 3, task 3.6 runs before the checkpoint 3.5. Contract and core groups run at high effort (`openspec/config.yaml`, operations).
