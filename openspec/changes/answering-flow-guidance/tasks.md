# Tasks

Each task writes its tests first and sees them fail for the right reason before implementing.

Terms used below:

- **"The check"** means `bun run build && GITHUB_TOKEN=$(gh auth token) bun run check`.
- **"File run"** means `ASKBOARD_E2E_ENGINES=chromium,firefox,webkit ASKBOARD_E2E_TARGET=session-process bun test ./packages/view/test/browser/<file>`, after `bun run build`. One browser process at a time on the machine. "In Chromium" means `ASKBOARD_E2E_ENGINES=chromium`.
- **"The fixture"** means `packages/view/test/browser/fixtures/answering-flow-asks.ts` from `answering-flow-fixes` (nine questions in three areas, sections, tabs and one question per view, en-US and it-IT, four recommendations, the TextFields "Service name" and "Ticket", a Tabs layout, and a single-question ask). A task that needs more (an area titled "Architecture" handing off to "Release", a postponed question, a widget-only question) adds it to the fixture, neutral content only.
- **"Dn"** and **"Qn"** refer to design.md. A requirement cited by name is in this change's delta specs. Report sections ("§3.3") are `drafts/ux-review-168/ux-review-report-1.1.0.md`.
- Commit bodies say `Refs #168`. Each group commits its own paths only (`git add <paths>`, never `-a`).
- Browser tests find the primary, Send, "Later", "Prefill recommended", the header jump, the delivery segments and the receipt through the harness's locators of task 2.1, never by label, except tests that assert a label itself. Every new browser file is listed in `packages/view/test/browser/harness/suites.ts` with no `engines` restriction. Waits are probes (`eventually`) or `quiet(reason)`, never fixed sleeps; no time bound is asserted outside the perf files.
- Italian strings outside report §4's accepted table are marked "(to review)" in EXPERIENCE.md's Voice and Tone (D5).

**Order and parallelism.** Group 0 first. Groups 1 and 2 may run in parallel: their files are disjoint (group 1: `packages/contract/**`, `packages/core/test/**`, `packages/server/test/**`, and `packages/core/src/config/**` or `packages/server/src/board-host/**` only if task 1.2 finds a gap, the spine, the PRD's FR-35; group 2: the attributes in `packages/view/src/shell/{question-actions,bottom-bar,board-header,question-card}.tsx`, `packages/view/test/browser/**`). While both run, each verifies with its own packages' commands and waits for the other's commit when the shared type check fails only in the other's files; the check runs at each review checkpoint. Groups 3 to 11 run one after the other, in that order: they share `board.tsx`, `question-card.tsx`, `bottom-bar.tsx`, the strings, `suites.ts`, EXPERIENCE.md, DESIGN.md and the browser lock. Group 9 starts only once `icon-set` (#210) is on `origin/main` and this branch is rebased on it (task 11.7's procedure, run early); if it is not, group 10 runs first and group 9 waits. Within a group, tasks run in order.
