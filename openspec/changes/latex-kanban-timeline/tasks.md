# Tasks

Each task writes its tests first and sees them fail for the right reason before it implements (the repository's TDD rule). "The check" means `GITHUB_TOKEN=$(gh auth token) bun run check` (it includes `check:skills`). "Coverage" means at least 80% of lines and functions for every file the task adds or changes, read from `bun test --coverage`'s per-file table. "Browser files" means the named files run with `bun packages/view/test/browser/run.ts --engines chromium,webkit` and the target the task names, under the browser lock. Every task that touches answers includes a test that the failing case appends nothing and publishes nothing (NFR-10, AD-10). Every string a component shows goes through the view's tables in en-US and it-IT (askboard-implementation, i18n), with the texts of `ux-update-draft.md`. After each task: `openspec validate --all --strict --no-interactive`, `bun run format` with `git status` showing only the task's files, the check; then tick the box with a note of about five lines (what was built, test counts, deviations) and commit in conventional form with no attribution, one commit per task. Contract versions follow askboard-contract-versioning (labels until task 7.2); appended export blocks and the chunk budget follow askboard-implementation.

Order: group 0 first, then group 1 (`contract`, at high effort). Then groups 2 (`core`, at high effort), 3 (`tools/build` and the widgets' shared code) and 4 (widget models) in parallel: they touch different packages and meet only through group 1's exports. Within them, task 4.1 follows task 3.1 (KaTeX installed) and task 4.3 follows task 3.2 (the shared time code). Group 5 follows groups 3 and 4, its tasks in order (task 5.1 moves the version constants); task 5.2 waits until the base holds `approval-scale-ranking`'s `dnd` chunk (its task 3.6), and task 5.4 until it holds the Approval's chunk (its task 5.1). Group 6 follows groups 2 and 5; group 7 last.
