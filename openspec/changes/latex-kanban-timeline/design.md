## Goals / Non-Goals

**Goals:**

- Each type is a registration: its own folders in `contract` and `widgets`, one registry line, its teaching text, its strings. The shared changes are generic: a diff shape, a changes check and package stylesheets, which later widgets reuse (the Diagram, Document review's Markdown, the Form).
- Every answer of the three carries only the changes its type declares, checked by `ask-core` whatever the board sends.
- KaTeX renders agent text as data, with no request.

**Non-Goals:**

- Resizing, adding or deleting entries, cards, lanes or columns; reordering cards within a column; a zoom control (proposal, open questions 5 and 6).
- A check that a range keeps its length (open question 9).
- The Diagram's renderers and their `renders` (`diagram-render`).

## Decisions

### 1. One change, three registrations (open question 1)

The three widen the same four sets, append to the same registry, strings, skill and chunk sizes, and give no result, so one binding and one rebase serve them. Registry order follows the PO's order: `latex`, `kanban`, `timeline`, after `main`'s types and `approval-scale-ranking`'s. Each type has `packages/contract/src/widgets/<type>/` (`<type>-props.json` `urn:askboard:input:<type>-props`, `<type>-changes.json` `urn:askboard:output:<type>-changes`, `constants.ts`, `checks.ts` plain with no Ajv so a chunk may import it, `wording.ts`, `widget.ts`, `index.ts`) and `packages/widgets/src/<type>/`. Nouns: "a LaTeX", "a Kanban", "a Timeline". No entry declares `result` or `derived`. FR-11's "Rendering" for LaTeX is the board's work and never reaches the agent.

### 2. The whole-field shape lands here (open question 2)

`ElementShape` gains `FieldsShape = {readonly fields: readonly string[]}`, with `diagram-render`'s name and semantics (its design decision 2, read at 9281d923). Over it, `elementChanges` compares each named field as a JSON value and gives `{op: "set", target: "<item>.<field>", value}`, with `null` for a field that is gone, in the shape's order. A named field holding `null` reads as absent, as in the list and keyed shapes: a `set` to `null` applies as a delete, so an edit that turns a field to `null` does not round-trip and `ask-core` refuses it (no type of this change admits a `null` field; `diagram-render` inherits the rule). A difference in any other key throws a problem naming the item and the key, which `ask-core` turns into a refusal. `applyElementChanges` sets the fields back with `define`, so that `__proto__` stays a key. A shape is told apart by `"fields" in shape`; no reader outside `element-diff.ts` reads `elements` (task 0.2 lists the readers). `spine-update-draft.md` blocks 1 and 2 carry `diagram-render`'s AD-20 blocks 3 and 4, with a LaTeX expression as the example. `diagram-render` drops its own task 1.1, its blocks 3 and 4 and its ADDED requirement of the same name, which this change's contract delta holds, and borrows `FieldsShape`.

*Alternatives:* the expression as a result `{expression}` (AD-20 keeps edits of agent content in values); LaTeX waiting for `diagram-render`, which comes later in the PO's order.

### 3. LaTeX's entry (open question 4)

Props `{expression}`, a string of 0 to `LATEX_EXPRESSION_MAX_CHARS` = 2,000 characters, `additionalProperties: false`. Characters are code points, as JSON Schema's `maxLength` counts them, in the schemas, `checks.ts` and its wording alike (group 1 review X-1). Shape `LATEX_SHAPE = {fields: ["expression"]}`. Changes: an array of `set`s whose target matches `^[A-Za-z0-9_-]{1,64}\.expression$` and whose value is a string of at most 2,000 characters. The contract never parses LaTeX (KaTeX is a view dependency), but its check reads the expression's control words and nesting in one linear pass, `scanLatex(text)` in `scan.ts`, which gives `{refused, depth}` and replaces task 4.5's `latexDefiningCommand` (group 4 review S-1; 4.7 re-review X-1 and X-2; 4.12 re-review X-1 and X-2; decision 7, Bounded work). Its refusal of definitions and internal names bounds KaTeX's expansion and runs before KaTeX on every path. Its depth is the agent's early answer at `ask`, `update` and in an answer, and since the 4.12 re-review it is no longer the bound the board relies on: that bound is KaTeX's own output (decision 7, Bounded output), because a hand reading of KaTeX's grammar missed nesting forms twice.

- Control words are read as KaTeX's lexer reads them: a backslash then `[A-Za-z@]+`, else a backslash and one character, so `\\def` is a line break and `\left` is not `\let`. `refused` is the first control word that defines a macro, one of `LATEX_DEFINING_COMMANDS` in `constants.ts` (KaTeX 0.19.1's `def` functions `\def`, `\gdef`, `\edef`, `\xdef`, `\global`, `\long`, `\let`, `\futurelet`, and its macros `\newcommand`, `\renewcommand`, `\providecommand`), or that holds `@`, KaTeX's internal names (`\df@tag`, `\current@color`, `\@ifnextchar`, …), which no author needs.
- `depth` is the most levels open at once, counted for the openers below; the scan is the agent's early refusal, and nesting it does not count (stacked combining marks) is bounded by the board's output bound (4.19 re-review X-1). `\show` and ``\char` `` are refused outright rather than emulating KaTeX's lexer for the token they consume. A level opens at `{`, `\bgroup`, `\begingroup`, `\begin` and `\left`, and closes at `}`, `\egroup`, `\endgroup`, `\end` and `\right`; the environment's name in braces after `\begin` or `\end` is no level, and a closer with no level open closes nothing (KaTeX refuses it). `^` and `_` open a level for their argument, which closes with the group that opens next if one opens before any other token (blanks skipped), else after the next token: `x^{y}` is 2 deep, `x^y` 1. Control symbols (`\{`, `\}`) are no level.
- An infix command, one of `LATEX_INFIX_COMMANDS` (KaTeX 0.19.1's `infix: true` functions `\over`, `\choose`, `\atop`, `\brace`, `\brack` and `\above`), adds one level to the group that holds it, the root included: it makes a fraction of everything before it in its group, so the numerator nests one level deeper with no brace (4.12 re-review X-1). In the same single pass, each open level keeps the deepest point reached inside it and whether it holds an infix, and on closing hands its parent that point, plus one if it held one: `a \over b` is 1, `{a \over b}` 2, and `\frac{` with `\over y}{x}` nested n times 2n. KaTeX allows one infix per group, so a group adds at most one.
- A brace KaTeX reads as text closes nothing, or a nest could hide behind closers that do not close (probed on 0.19.1: `\sqrt{%` and a line feed, `\sqrt{\verb|}|`, ``\sqrt{\char`}`` and `\sqrt{\show}`, each repeated 10 times with 10 closing braces, nest 10 deep). In a comment, from a `%` to the next line feed, and in a `\verb` body, read as KaTeX's lexer reads it (`\verb` or `\verb*`, a delimiter, then up to the same delimiter before the line ends), closers count for nothing while openers still count, so a reading that differs from KaTeX's only refuses more: inside `\url{…}` and `\href{…}`, KaTeX reads `%` as a character, and the scan, ignoring the closers after it, counts more, never less. After `\char` and a backquote, and after `\show` and its blanks, the next character or control sequence is consumed and is no group, unless it is an opener (`{` or a word of `LATEX_LEVEL_OPENERS`), which is left to be counted: KaTeX's lexer drops blanks only after a control word, so after a backquote or a comment a blank is a space token, which `\char` and `\show` take, and the opener after it is a real group (4.12 re-review X-2). Where the scan and KaTeX then differ, the scan counts more; a consumed closer still closes nothing.
- KaTeX 0.19.1 lets no command stand unbraced as its own argument (`\frac \frac x x x` fails: "Unexpected end of input in a macro argument"), so arguments nest only through groups and scripts; a source guard keeps it so (task 4.9).

`latexPropsProblems` words a definition "the expression defines a macro with `\def`, which a LaTeX item does not allow", an internal command "the expression names `\df@tag`, one of KaTeX's internal commands, which a LaTeX item does not allow", and a depth past `LATEX_NESTING_MAX_DEPTH` "the expression nests {depth} levels deep, more than the limit of {limit}" (the depth as read; the limit as task 4.15 measures it, decision 7). The scan reads every character once, with no nested quantifier and no backtracking, and runs only on a text within the 2,000 code points. The registry runs the check on what an agent sends and, through `valuesProblem`, on an answer's edited value, so `ask-core` refuses either. No schema set moves: these are checks, not schemas. Skill draft: use "one mathematical expression in LaTeX that the user reads and corrects, with a live preview"; notes "The answer's change is one `set` of `<id>.expression`: the whole expression as the user wrote it, which may not parse." and "KaTeX renders it: `\href`, `\url` and `\includegraphics` show no link or image; a macro definition (`\def`, `\newcommand`, …), a KaTeX internal command (a name holding `@`) and a nest deeper than `LATEX_NESTING_MAX_DEPTH` levels are refused." Example: `{type: "latex", id: "formula", props: {expression: "x = \\frac{-b \\pm \\sqrt{b^2-4ac}}{2a}"}}`.

### 4. Kanban's entry

Props: `columns`, 2 to 12 `{id, label}` (label 1 to 60), and `cards`, 1 to 200 `{id, label, description?, column}` (label 1 to 200, description 1 to 500), each `additionalProperties: false`. `checks.ts`: IDs unique across columns and cards (AD-7, child IDs within their item); each card's `column` names a column. Problems name the element: `card "fix-login"`. Shape `{elements: "cards"}`. Changes: `set`s only, target `^<id>\.<id>\.column$`, value an ID. Skill draft: use "cards the user moves between 2 to 12 columns, such as statuses, priorities or owners"; note "Each card names its `column` by ID; the answer's changes are `set`s of `<id>.<card>.column`. The user only moves cards: their order, labels and the columns stay." Example: three columns, three cards.

### 5. Timeline's entry

Props: `lanes`, 1 to 20 `{id, label}` (label 1 to 60), and `entries`, 1 to 200 `{id, label, lane, date?, start?, end?}` (label 1 to 200), dates in the Gantt's `fullDate` pattern. `checks.ts`: IDs unique across lanes and entries; `lane` names a lane; an entry holds `date` alone or `start` and `end` together ("an entry holds `date` alone, a milestone, or `start` and `end`, a range"); every date exists and lies within `GANTT_FIRST_DATE` and `GANTT_LAST_DATE`, through the date checks the Gantt's props use; `end` is on or after `start`. One object schema with optional dates and the rule in the check gives one worded problem, where a `oneOf` would need a `schemaErrors` hook. Shape `{elements: "entries"}`. Changes: `set`s only, target `^<id>\.<id>\.(lane|date|start|end)$`, value an ID or a full-date; never `null`, so no date can be removed. A milestone given an `end`, or a range losing one, is refused by the edited props' check. Skill draft: use "milestones and date ranges the user moves in time and across lanes, as in a roadmap"; note "An entry is a milestone with `date` or a range with `start` and `end` (inclusive), in a `lane`; the answer's changes are `set`s of `lane`, `date`, `start` and `end`." Example: two lanes, a range and a milestone.

### 6. Changes checked against their type (open question 8)

`contract` exports `widgetChangesProblems(item: {type, id}, changes, types = WIDGET_TYPES): readonly Problem[]`, beside `widgetResultProblems`. It validates `changes` against the entry's `edits.changes` through the shared widget validator, compiled once per type, and prefixes `item <id>: `, returning every problem. An entry without `edits` refuses any change; an unknown type gives none. In `widget-values.ts`, step 3 computes each value's changes once, inside `roundTripProblem`'s `try`, so a throw of `elementChanges` (a fields shape's unnamed key) is a refusal naming the item and the key, the key cut as `operationOf` cuts a target; the round trip runs on them, then `widgetChangesProblems`, with `[]` for a type that has no shape (Approval and Ranking answers carry no changes); the first problem refuses the answer (`content`), so nothing is appended, kept or published. The changes check stays after `valuesProblem`, whose props bounds keep its input small (group 1 security review). A decline carries no value and runs nothing. `core` names no type. The check runs for every type: task 2.1 replays the Tree, Gantt, WBS and Gantt plan suites, and a Tree or Gantt edit that fails its own schema stops the task for `/opsx:update`. `spine-update-draft.md` block 3 records the rule in AD-20.

*Alternative:* a check in each new type's `checks.ts` comparing sent and edited values, a new registry seam that duplicates the changes schema.

### 7. The LaTeX component (open questions 3 and 4)

`packages/widgets/src/latex/`:

- `render.ts`: one options object built fresh for each call: `displayMode: true`, `throwOnError: true`, `trust: false` (the literal, never a function), `strict: "ignore"`, `maxExpand: 1000`, `maxSize: 20`, `output: "htmlAndMathml"`, and `macros: {}` new each time, so `\gdef` never outlives a render. `renderInto(element, expression, bounds = LATEX_TREE_BOUNDS)`, in order (task 4.16):
  1. runs decision 3's `scanLatex`: a refused command or a depth past `LATEX_NESTING_MAX_DEPTH` gives `{refused: {command}}` or `{refused: {depth, limit}}`, and KaTeX is not called;
  2. builds KaTeX's output tree with `renderTree` (`tree.ts`, Bounded output below) and measures it with `treeSizeOf`: past `bounds` it gives `{tooComplex: {depth, nodes, fractions}}` and makes no node;
  3. else makes the tree's nodes (`tree.toNode()`, which builds them and sets styles through the CSSOM, as `katex.render` does) and puts them in place of the element's children.

  It catches every error, not only `ParseError` (a browser's smaller stack may throw a `RangeError` on a deep nest): an `Error` gives `{error: message}`; any other thrown value gives a failure with no text, for which the component shows the string tables' "The expression could not be drawn." (task 5.1 moves the English literal task 4.1 built out of `render.ts`). Any failure leaves the element as it was, so the preview keeps its last good render, which a test checks with real KaTeX (as built in task 4.1; the scratch `span` task 4.1 needed, because `katex.render` empties its target before it parses, `katex.mjs:16313`, goes, since no node exists before the tree is measured). `parseProblem(expression, bounds)` runs steps 1 and 2 without making nodes, for unit tests in Bun (no DOM). Every caller of `render.ts` is bounded, not only the component, and no module of `packages/widgets/src` calls `katex.render` or `katex.renderToString`.
- **Bounded work** (group 4 review S-1 and the 4.7 re-review's X-1 and X-2, folded on 2026-11-07). `maxExpand` counts expansions, not the tokens they emit, so `\def\b{<900 x>}\def\a{\b…\b}\a` within 2,000 code points drew 36,011 nodes in 3.3 seconds in Chromium at 998 code points and did not finish in 280 seconds at 1,998. The bounds on expansion are on the source, in decision 3's `scanLatex`, run by the contract on what reaches `ask-core` and by `renderInto` before KaTeX. The bound on nesting is on KaTeX's output, measured by `renderInto` before any node exists (4.12 re-review X-1 to X-3 and U-1, folded on 2026-11-07):
  - *No definitions.* No expression holding a macro definition renders.
  - *No internal names.* KaTeX also defines macros by side effect: `\tag` defines `\df@tag` and `\color` defines `\current@color` with the author's text (`katex.mjs:14007`, `:7748`), and its lexer reads `@` as a letter, so the source can call them: `\current@color` typed 78 times after a 900-glyph color took 10.2 seconds, and the two combined drew 504,228 nodes in 18.6 seconds at 1,636 code points in Chromium (4.7 re-review X-1). Every control word holding `@` is refused. Task 4.5's claims, that the list held "every way KaTeX defines a macro" and that none of KaTeX's macros repeats its argument, were false. What holds is narrower: of the control words without `@`, none drew more than 3.4 times the markup of its 200-glyph argument three deep (task 4.5's probe), and a source guard (task 4.8) checks that every name `katex.mjs` defines by side effect (`macros.set(` with a literal name, a `\gdef` in a macro's body) holds `@` or has a fixed body (`\cr`, `|`, `\|`), and that no macro whose name lacks `@` calls a name defined with author text. A bound on the calls of internal or author-defined macros is then not needed: no macro the source can call holds author text.
  - *Bounded output.* Output size does not bound render cost. Without any macro, about 130 nested vertical-list constructs (`x^{`, `\sqrt{`, `\frac{…}{x}`, `\hat{`, `\overbrace{`, `\cancel{`, `\stackrel{x}{`, `\boxed{`; 521 code points for `x^{`) crash Chromium's renderer, and the parent page with the sandboxed frame; and WebKit's MathML layout doubles with each directly nested fraction (18 deep: 1.4 seconds; 20: 5.4; 30: over 30) (4.7 re-review X-2). A hand count of KaTeX's grammar missed two ways to nest within its limit: infix fractions (`\frac{` with `\over y}{x}` at a counted 11: no answer in 15 seconds in WebKit) and openers hidden after `\char` or `\show` (130 hidden levels counted 0 and crashed Chromium) (4.12 re-review X-1 and X-2). So the board bounds what KaTeX makes, not a reading of its grammar:
    - `tree.ts` (task 4.14): `renderTree(expression, options)` calls KaTeX's `__renderToDomTree`, the function `katex.render` itself calls before it makes nodes (`katex.mjs:16312-16316`: `renderToDomTree(expression, options).toNode()` appended), so drawing the measured tree is drawing what `katex.render` would; with `throwOnError: true` it throws as `katex.render` does (`renderError`). `treeSizeOf(tree)` walks the tree through `children`, the one field every node class of 0.19.1 holds its sub-nodes in (`Span`, `Anchor`, `SvgNode`, `MathNode`, `DocumentFragment`), with an explicit stack, giving `{depth, nodes, fractions}`: `fractions` is the most MathML fractions nested on one path from the root, a fraction being a node whose `type` is `"mfrac"` (KaTeX's `MathNode`; the HTML half's spans of class `mfrac` have no `type` and do not count), counted in the same walk (task 4.20). Past `LATEX_TREE_MAX_DEPTH`, `LATEX_TREE_MAX_NODES` or `LATEX_TREE_MAX_FRACTIONS` (`LATEX_TREE_BOUNDS`, in `tree.ts`) nothing is drawn: the field error says the expression is too complex to preview, in the editable item, the read-only item and a Snapshot alike, and "Answer" is not blocked, as for a parse error (open question 3).
    - Two causes, two bounds (task 4.15's first run, folded on 2026-11-07). Depth crashes Chromium: about 130 nested vertical-list constructs, each adding 4 to 14 levels to the output by construct (`\frac{` nested 14 deep gives depth 105, `x^{` 105, `\sqrt{` 90, the review's infix form at a counted 10 gives 147 and its hidden form at 20 levels 167, while the skill's example gives 25, 2,000 glyphs 8 and a 400-cell matrix 14). WebKit's cost is the nesting of MathML fractions, not depth: over the first run's WebKit rows, 11 or fewer nested `mfrac` gave no render at 500 ms or more (slowest 386 ms, tree depth to 182), 12 gave one (`\boxed{` with `\over y}` side by side 24 deep, 638 ms), 13 or more gave 574 ms to 6.0 s, and no `mfrac` gave none to tree depth 245 (141 ms). A depth bound low enough for WebKit's fractions (95) would refuse nests the board draws in milliseconds and puts the scan's limit at 6. So `treeSizeOf` counts nested fractions beside depth and nodes, the fraction bound caps WebKit's chain, the depth bound stays within what both engines drew without a crash (the sweep reached tree depth 319 in Chromium; the crash 4.12's review saw came from a far deeper hidden nest), and the node count bounds width (2,000 glyphs: 4,012 nodes; `\dfrac` nested 14 deep side by side to 1,860 code points: 4,415). Forms a hand count misses, today's and those a KaTeX release adds, are bounded by construction, as long as KaTeX draws its fractions as `mfrac` (Internal API, guards (l) and (m)).
    - The work before the bound acts is KaTeX's parse and build in script, about linear in the source once definitions and internal names are refused and expansions capped (`maxExpand`): under 3 ms for each form above in Bun; task 4.15 measures it in both engines.
    - Internal API. `__renderToDomTree` is not in KaTeX's types and its documentation calls it unstable; it is acceptable only with the exact pin and guards (task 4.14): `render.test.ts` fails if the pinned `katex.mjs` stops exporting it, if `render` stops being `renderToDomTree(…).toNode()` appended, or if `renderToDomTree` stops rethrowing under `throwOnError` (`:16347`); a dynamic guard checks, over every control word and the seeded expressions, that the walk's depth and node count are at least the tag depth and start tags of `tree.toMarkup()`; and `renderTree` reads the function with a run-time check, so its absence is an error and no render (fail closed). Two more guards (task 4.20) catch a KaTeX that draws fractions differently: (l) the pinned `katex.mjs` creates `mfrac` at one site, `new MathNode("mfrac", …)` in `genfrac`'s MathML builder, and the MathML element names it creates (the literal names of `new MathNode("…"` and the computed sites, each with its line) equal a pinned list, so a release that adds an element, a site, or builds fractions elsewhere fails until the list is re-read and task 4.15's probe re-run; (m) each fraction command (`\frac`, `\dfrac`, `\tfrac`, `\cfrac`, `\genfrac`, `\binom`, `\dbinom`, `\tbinom`) and each of `LATEX_INFIX_COMMANDS`, nested 3 deep, gives `fractions` 3, and over guard (k)'s expressions `fractions` equals the deepest nesting of `<mfrac` tags in `tree.toMarkup()`.
    - Why the output tree, not the parse tree (`__parse`, considered first): the output is what the page lays out, so its depth is the cause the bound caps, where one parse node maps to a different output depth per node type; it is built once and drawn from the same tree, where `__parse` would parse twice; and its walk reads one field, where parse nodes hold their children under many names beside `loc`, which holds the lexer and the source. Measuring KaTeX's tree before drawing, rejected before task 4.5 because the parse did unbounded expansion, is safe since definitions and internal names are refused before KaTeX runs.
    - Measuring (task 4.15, replacing task 4.10's rule; 4.12 re-review X-3; rules amended on 2026-11-07 after its first run). Fixtures: task 4.10's constructs; every control word with arguments nested in each argument position; the infix forms; the hidden-opener forms; `\left…\right`; environments; a style-wrapped form; each alone, side by side to 2,000 code points and branching; and a combined form, the slowest fraction family at the fraction bound inside the deepest family without fractions up to the depth bound. Each is timed in Chromium and WebKit with KaTeX's fonts and measured in Bun (scan depth, tree depth, nodes, fractions). Flat content past 2,000 code points (the probe calls KaTeX directly) sets the node bound. The margin stays a factor of 4 to the 2-second requirement: every fixture within the bounds renders in under 500 ms on the measuring machine, since typical laptops and CI runners are 1.5 to 3 times slower single-threaded and WebKit's cost grows about 1.7 times per nested fraction (first run: 229 ms at 10, 386 at 11, 638 at 12). A 1-second margin would admit 12 fractions and leave a factor of 2; a tighter one would refuse 11 for no realistic expression's sake. Rules, in order:

**Font licences** (task 3.4; corrected on 2026-11-07, when task 3.1 read the fonts' name tables). A font file can carry a licence other than its package's: KaTeX's `LICENSE` says MIT, its fonts' name tables say SIL OFL-1.1 with Reserved Font Names. The adoption rule admits OFL-1.1 only for unmodified font files shipped with their licence text, and `tools/licence-texts.json` serves only packages that ship no licence file, so it does not fit. The mechanism:

- `tools/font-licences.json`, keyed `<name>@<version>` like `licence-texts.json`: for a package whose fonts a chunk inlines, `{licence, fonts, derived, source, date, reason, text}`, where `fonts` is the font folder within the package (`dist/fonts` for KaTeX), `derived` the package's files whose code holds glyph outlines its upstream derived from those fonts (`["dist/katex.mjs"]`, the file Bun bundles for `import "katex"`, whose `var path = {` holds what `dist/katex.js:6970-6974` says is adapted from the KaTeX fonts under OFL-1.1; group 3 review X-1; an empty list when there are none), `licence` is an SPDX ID that is `OFL-1.1` or one `tools/check-licences.ts`'s `classify` calls permissive (any other fails the build, so the table admits nothing outside the rule), and `text` is the whole notice for the fonts: a first line naming the package version, the folder and the `derived` files, the fonts' copyright lines with every Reserved Font Name as their nameID 13 gives them, then the licence's full text. `source` is the licence text at a commit (default: `spdx/license-list-data`'s `text/OFL-1.1.txt` at a pinned commit, its template copyright line replaced by the fonts' lines, which `reason` says), never fetched by the build. One entry today: `katex@0.19.1`, `OFL-1.1`.
- `loadChunkStylesheets` reports, per chunk, the package (`<name>@<version>`, from the innermost `node_modules/<name>` folder on the stylesheet's path and its `package.json`) of each stylesheet whose fonts it inlined; a stylesheet with an inlined font outside any package fails the build, naming the chunk and the stylesheet. The listed stylesheets' files join the chunk's inputs for `collectNotices`, so the package has a notice even when the chunk's script does not import it.
- `collectNotices` takes the table (default `FONT_LICENCES`): the notice of a package version that has an entry reads `licence: "<package licence> AND <entry licence>"` (the package's expression in parentheses when it holds a space), `"MIT AND OFL-1.1"` for KaTeX, and its text is the package's own text, a blank line, then the entry's text; it records the key it took. It applies wherever that package version's notice is collected, so its notice stays one file at one `licencePath` (the build writes notices by path, and a Snapshot keeps one notice per package and version, `view/src/assemble/licences.ts`).
- The build fails when a chunk inlines fonts of a package version with no entry, and on an entry no chunk used, neither through its inlined fonts nor through a `derived` file among its inputs (stale, as `staleLicenceTexts`). A chunk that bundles KaTeX's script without its stylesheet still gets the `MIT AND OFL-1.1` notice, since the entry applies wherever the package version's notice is collected. A version bump of `katex` therefore fails the build until the entry is re-read and re-keyed.
- A `tools/build` test keeps each entry true to its fonts: it reads the `name` table of every `.ttf` the entry's `fonts` folder holds (the build drops them, the package ships them) and checks that an `OFL-1.1` entry matches fonts whose nameID 13 says "SIL Open Font License, Version 1.1", that every Reserved Font Name and copyright line they declare stands in the entry's text, and that each `derived` file exists in the package.

- [A Tree or Gantt answer that fails its own changes schema is now refused] → task 2.1 replays every Tree, Gantt, WBS and Gantt plan suite before the check is on; a failure stops for `/opsx:update`, never a schema widened in passing.

The source guards of tasks 4.8, 4.9 and 4.13 still read `katex.mjs` for names defined by side effect, unbalanced macro bodies, raw-token commands, infix commands and unbraced arguments, and task 4.15 renders every control word in every argument position at the bounds; a KaTeX bump fails `render.test.ts` until all of them are re-read.
- [A macro repeats its argument in a way the guards miss] → definitions and internal names are refused before KaTeX, expansions are capped, and the node bound refuses an output too wide to lay out in time.
- [KaTeX's internal `__renderToDomTree` changes or goes] → the exact pin, the source guards of task 4.14, and a run-time check that fails closed (no render).
- [A KaTeX release draws fractions with another element, or another element takes on WebKit's per-level cost] → guards (l) and (m) of task 4.20 fail on a new MathML element, a new `mfrac` site or a fraction command that no longer counts, and the exact pin re-runs task 4.15's probe on any bump; until then, depth and nodes still bound the output.

- [Many LaTeX items make the first draw of a board slow] → the render queue draws one item per task and an edited item first, so the board answers between draws (decision 7, Many items); the last preview of a large board arrives late, never the board's answer to input.
- [lightningcss reads CSS unlike a browser] → it parses by CSS Syntax as Tailwind's own engine does, and task 3.9's tests hold every form the three reviews found; styles it cannot parse fail the build; the page policies stay the run-time defence (`default-src 'none'`, `img-src data: blob:`, hash-only `style-src`).

- [The LaTeX chunk is about 650 KB, 370 KB of it fonts] → only boards with a LaTeX item take it; task 5.1 records the size with its reason. A fonts chunk shared with a future MathLive is not needed while MathLive is out (renderer row 13).
- [Two KaTeX versions with the Diagram] → Mermaid brings its own 0.18 (renderer D5); a board with both carries both, as the spike measured; no change here.
- [Packed tracks guess label widths] → labels are cut at 200 pixels with the whole label in the accessible name and title; an overlap shows a cut label, never a lost entry.
- [Native drag fails by hand in Safari] → the keyboard moves answer; task 6.6 records the PO's check; a failure is a later change to pointer drag, as for the Ranking.
