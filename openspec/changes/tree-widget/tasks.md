# Tasks

Each task writes its tests first and sees them fail for the right reason before it implements (the repository's TDD rule). "The check" means `GITHUB_TOKEN=$(gh auth token) bun run check`; "the browser suite" means `bun packages/view/test/browser/run.ts --engines chromium,firefox,webkit` (an option goes before `--`, as in `-- -t <name>`). After each task: `openspec validate --all --strict --no-interactive`, `bun run format` with `git status` showing only the task's files, the check, and the browser suite when the task touches `packages/view`, `packages/widgets` or `tools/build/`; then tick the box with a `  - Note:` (what was built, the choices made, the evidence) and commit in conventional form with no attribution.

## Scope and order

- **May change:** `packages/widgets/`; new files under `packages/contract/src/widgets/` (`element-diff.ts`, `validator.ts` and `tree/`), `packages/contract/src/fixtures/` and `packages/contract/test/`; one appended export block in each of `packages/contract/src/index.ts`, `validate.ts` and `fixtures/index.ts` (design, Merge points); `packages/view/src/` and `packages/view/test/browser/` (design decisions 7 and 9); `packages/view/chunk-sizes.json`; `tools/build/`; `bun.lock` in task 1.1 only; `packages/contract/package.json` by task 2.1 only, the integration's own commit.
- **Never changes:** E1's schema files, `sets.ts` (`SCHEMA_SETS`, `SCHEMA_IDS`), constants and existing fixtures; every other `package.json`, `tsconfig*.json` and the lockfile beyond 1.1; `packages/core`, `server`, `compute`; `docs/` (spine changes are drafted in `spine-update-draft.md`); `openspec/changes/e1-walking-skeleton/`; `.claude/commands/opsx/` and `.claude/skills/openspec-*`; any other worktree.
- **Order:** the widget-neutral seams (group 2) come right after the workspace, so the Gantt branch can cherry-pick them (design decision 12), and 2.11 lands before group 3, whose validators refuse a `null` position; the Tree's contract (group 3) and edit model (group 4) follow; the Tree chunk (group 5) and the widget host (2.9) come before the component (group 6), so that each component task's browser scenarios fail first against the build before it.
