# Tasks

Each task writes its tests first and sees them fail for the right reason before it implements (the repository's TDD rule). "The check" means `GITHUB_TOKEN=$(gh auth token) bun run check`; "the browser suite" means `bun packages/view/test/browser/run.ts --engines chromium,firefox,webkit` (an option goes before `--`, as in `-- -t <name>`). After each task: `openspec validate --all --strict --no-interactive`, `bun run format` with `git status` showing only the task's files, the check, and the browser suite when the task touches `packages/view`, `packages/widgets` or `tools/build/`; then tick the box with a `  - Note:` (what was built, the choices made, the evidence) and commit in conventional form with no attribution.

## Scope and order

- **May change:** `packages/widgets/`; new files under `packages/contract/src/widgets/tree/`, `packages/contract/src/fixtures/` and `packages/contract/test/`; one appended export block in each of `packages/contract/src/index.ts`, `validate.ts` and `fixtures/index.ts`, and two appended entries in `sets.ts` (design decision 2); `packages/view/src/` and `packages/view/test/browser/` (design decisions 7 and 9); `packages/view/chunk-sizes.json`; `tools/build/`; `bun.lock` in task 1.1 only.
- **Never changes:** E1's schema files, constants and existing fixtures; every other `package.json`, `tsconfig*.json` and the lockfile beyond 1.1; `packages/core`, `server`, `compute`; `docs/` (spine changes are drafted in `spine-update-draft.md`); `openspec/changes/e1-walking-skeleton/`; `.claude/commands/opsx/` and `.claude/skills/openspec-*`; any other worktree.
- **Order:** the build integration (group 5) and the widget host (group 6) come before the component (group 7), so that each component task's browser scenarios fail first against the build before it.
