# Tasks

Each task writes its tests first and sees them fail for the right reason before it implements (the repository's TDD rule). "The check" means `GITHUB_TOKEN=$(gh auth token) bun run check` (it includes `check:skills`). "Coverage" means at least 80% of lines and functions for every file the task adds or changes, read from `bun test --coverage`'s per-file table. "Browser files" means the named files run with `bun packages/view/test/browser/run.ts`, the target the task names, at DESIGN's 1,280-pixel floor, in Chromium and WebKit, and in Firefox too where the task says so; a Firefox run that cannot happen locally goes to a CI dispatch named in the note. Browser runs take the cross-session lock in the same command, in the background or with the maximum tool timeout (600000 ms): `L=/Users/mr/git/MrBogomips/askboard/.git/askboard-browser.lock; mkdir "$L" && echo $$ > "$L/pid" && trap 'rm -f "$L/pid"; rmdir "$L"' EXIT INT TERM HUP && bun run build && bun packages/view/test/browser/run.ts …`; when `mkdir` fails, wait and retry: the lock is stale only when `kill -0 $(cat "$L/pid")` fails. "Nested" in a test means at least two layouts deep, one of them a Tabs. Every task that touches answers includes a test that the failing case appends nothing and publishes nothing (NFR-10, AD-10). Every element that shows agent or user text gets a wrap class, checked with 200 characters and no space. A prototype name (`__proto__`, `constructor`) is tested wherever agent or user text becomes a key or an ID. Every string a component shows goes through the view's tables in en-US and it-IT (askboard-implementation, i18n), with the texts of `ux-update-draft.md` block 1. After each task: `openspec validate --all --strict --no-interactive`, `bun run format` with `git status` showing only the task's files, the check; then tick the box with a note of about five lines (what was built, test counts, deviations) and commit in conventional form with no attribution, one commit per task. Contract versions follow askboard-contract-versioning (labels until task 8.2); appended export blocks and the chunk budget follow askboard-implementation.

Order: group 0 first. Then groups 1 (`contract`, at high effort; its fix tasks 1.7 to 1.9 included) and 4 (`view`'s renderer and the board page's links) in parallel: group 4 edits only `view`, `tools/build` and `tools/check-imports.ts`. Group 2 is withdrawn. Group 3 (`core`, at high effort) follows group 1. Group 5 follows groups 1 and 4. Group 6 follows groups 3 and 5, its tasks in order (task 6.3 moves three constants). Group 7 follows group 6; group 8 last.
