# Tasks

Each task writes its tests first and sees them fail for the right reason before it implements (the repository's TDD rule). "The check" means `GITHUB_TOKEN=$(gh auth token) bun run check` (it includes `check:skills`). "Coverage" means at least 80% of lines and functions for every file the task adds or changes, read from `bun test --coverage`'s per-file table. "Browser files" means the named files run with `bun packages/view/test/browser/run.ts --engines chromium,firefox,webkit` and the target the task names, under the browser lock; an engine that cannot run locally is named in the note for the CI dispatch (askboard-implementation, test-harness patterns). "Nested" in a test means at least two layouts deep, one of them a Tabs. Every task that touches answers includes a test that the failing case appends nothing and publishes nothing (NFR-10, AD-10). Every string a component shows goes through the view's tables in en-US and it-IT, with the texts of `ux-update-draft.md`. After each task: `openspec validate --all --strict --no-interactive`, `bun run format` with `git status` showing only the task's files, the check; then tick the box with a note of about five lines (what was built, test counts, deviations) and commit in conventional form with no attribution, one commit per task. Contract versions follow askboard-contract-versioning (labels until task 5.2); appended export blocks and the chunk budget follow askboard-implementation.

Order: group 0 first, then group 1 (`contract`, at high effort). Then groups 2 (`core`, at high effort) and 3 (`view`) in parallel: they touch different packages and meet only through group 1's exports and the source guard, to which each appends its own tables; group 3's tasks run in order (task 3.2 moves the three versions), task 3.1 at high effort, since it switches every reader of the shell and the board page. Group 4 follows groups 2 and 3; group 5 last.
