## Facts the criteria depend on

| # | Fact | Page | Criteria |
| --- | --- | --- | --- |
| D1 | A plugin entry's `source` can be `command`: "a directory produced by running a command on the machine where the plugin is installed". Fields `command` (printable ASCII, at most 500 characters, no run of four spaces; prints one absolute path and exits 0), `timeout` (1 to 600 s, default 60) and `mode` (`copy`, default, or `link`). Requires Claude Code 2.1.229 or later. | `plugins/marketplace-reference.md`, "command plugin source" | 3 |
| D2 | The command runs through `sh` from the user's home directory, or through `cmd.exe` on Windows. | same | 3, 11 |
| D3 | Copy mode copies the printed directory into the plugin cache and fails above 256 MiB or 20,000 entries; the version is a hash of the copied files (`<manifest version>-<hash>` when the manifest sets one). Link mode loads in place, has no size limit, and is refused on Windows. | same; `plugins/loading.md`, version | 1, 3 |
| D4 | Claude Code runs the command at every install and update, once per session in the background shortly after start for each enabled command-sourced plugin (independent of auto-update and `DISABLE_AUTOUPDATER`), and at startup when the installed version is missing from the cache. `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` skips the two background runs, not installs or updates. A changed hash installs a new version and reloads the plugin in the running session (or asks for `/reload-plugins` when that would invalidate the prompt cache). | `plugins/loading.md`, "When a command source re-runs" | 2, 3, 5 |
| D5 | The user sees the whole command and accepts it before it runs; a script passes `--yes` to `claude plugin install`. A changed command or mode must be accepted again: until then the background runs stop and `/plugin` shows an error with the `claude plugin update` command to run. | `plugins/install.md`, "Install from your shell"; `plugins/host-marketplace.md`, "Change the command of a command source" | 3 |
| D6 | Managed `disableCommandPluginSources` turns command sources off. | `plugins/marketplace-reference.md`; `plugins/host-marketplace.md` | 3 |
| D7 | `npm` source: fetched with the user's npm client; install scripts never run; dependencies are not installed during the fetch, only from a supported lockfile in a separate step with scripts disabled; a tarball link on github.com (including a release download) is refused. | `plugins/marketplace-reference.md`, "npm plugin source" | 3 |
| D8 | `archive` source: one zip per entry, `https` only, never a loopback host, at most 256 MiB, 120 s, five redirects. | `plugins/marketplace-reference.md`, "archive plugin source"; `plugins/host-marketplace.md`, download limits | 3 |
| D9 | `${CLAUDE_PLUGIN_DATA}` is `~/.claude/plugins/data/<id>/` (the plugin ID with characters other than letters, digits, `_` and `-` replaced by `-`), created on first reference, kept across plugin updates, and substituted in a stdio server's `command`, `args` and `env`. | `plugins-reference.md`, environment variables | 2, 4, 16 |
| D10 | Uninstalling a plugin from the last scope it is installed at deletes its options, secrets and data directory `~/.claude/plugins/data/<id>/`, except with `--keep-data`, when another installed plugin uses the same folder, or when Claude Code cannot read back the installed list. | `plugins-reference.md`; `plugins/cli-reference.md`, "plugin uninstall", "What an uninstall deletes and keeps" | 16 |
| D11 | Files under a plugin's top-level `bin/` are on the Bash tool's `PATH`; claude.ai and Cowork do not install a plugin that has `bin/`. | `plugins-reference.md`, directory table | 3 |
| D12 | `MCP_TIMEOUT`: server startup timeout, default 30,000 ms. MCP startup is non-blocking by default: servers connect in the background and their tools appear as they finish (`MCP_CONNECTION_NONBLOCKING=0` makes startup wait, `MCP_CONNECT_TIMEOUT_MS` 5,000 ms for that batch). | `env-vars.md`; `mcp.md` | 2 |
| D13 | A stdio server whose first connection fails: an interactive session marks it failed (Reconnect in `/mcp`); a `claude -p` run continues without its tools. When a plugin provides the server, new sessions and `-p` runs skip it for 15 minutes after a failure, with `Skipping connection (recent failure cached; retries automatically in 15 min, or edit the plugin config to retry now)`; a session that started during the 15 minutes does not retry when they end. Changing the server's `command`, `args` or `env` retries at once. Before 2.1.307 the message was a timeout message. | `mcp.md`, "Stdio servers that exit or fail to start"; `errors.md`, "Skipping connection" | 14 |
| D14 | With tool search (on by default), Claude Code tells the model which server failed and its connection error; without tool search it does not. | `mcp.md`, "How Claude learns that a server failed" | 14 |
| D15 | Claude Code asks stdio servers for protocol revision 2026-07-28 by default; `MCP_PROTOCOL_NEGOTIATION=legacy` keeps every server on the earlier handshake. | `mcp.md`, channels | 14 |
| D16 | On Windows, substituted plugin paths use forward slashes (`C:/Users/...`), and hooks run through PowerShell when Git Bash is not installed; Claude Code closes a stdio server's stdin and ends its process tree 300 ms later. | `plugins-reference.md`; `mcp.md` | 11 |
| D17 | `bun build --compile --target`: `bun-linux-x64`, `bun-linux-arm64` (glibc), `bun-linux-x64-musl`, `bun-linux-arm64-musl`, `bun-darwin-x64`, `bun-darwin-arm64`, `bun-windows-x64`, `bun-windows-arm64`. On x64 one binary targets Nehalem (SSE4.2) and picks AVX2 or AVX-512 paths at run time; `-baseline` and `-modern` resolve to the same binary. | Bun `docs/bundler/executables.mdx` | 1 |
| D18 | Unsigned macOS executables get Gatekeeper warnings; `codesign` with the JIT entitlements (`allow-jit`, `allow-unsigned-executable-memory`) signs them. | Bun `docs/bundler/executables.mdx`, "Code signing on macOS"; `docs/guides/runtime/codesign-macos-executable.mdx` | 2 |
| D19 | Bun statically links JavaScriptCore and WebKit (LGPL-2; WebCore files LGPL-2) and tinycc (LGPL-2.1). Relink steps: clone `oven-sh/WebKit` to `vendor/WebKit`, `bun sync-webkit-source` (checks out `WEBKIT_VERSION` from `scripts/build/deps/webkit.ts`), `bun run build:local`. | Bun `LICENSE.md`, `docs/project/license.mdx` | 6, 7 |
| D20 | TinyCC is built into Bun everywhere except Android and FreeBSD (`tinycc = !(abi === "android" \|\| freebsd)`), and is used only by `bun:ffi`'s `cc()`. | Bun `scripts/build/config.ts`, `scripts/build/deps/tinycc.ts`, `docs/runtime/ffi.mdx` | 6 |

## Differences from the design documents

| # | Design text | Documentation | Effect |
| --- | --- | --- | --- |
| X1 | AD-22 and SOLUTION-DESIGN §8: "uninstalling leaves `.askboard/`, the session-file folder, and the executable cache" | D10: the last uninstall deletes `${CLAUDE_PLUGIN_DATA}`, which holds the cache (AD-22 puts it at `${CLAUDE_PLUGIN_DATA}/bin/<version>/`), unless `--keep-data` | AD-22's uninstall sentence is wrong for the cache (criterion 16 checks it in the isolated configuration) |
| X2 | §10.4 criterion 2 and §4.10: a cold start "within `MCP_TIMEOUT` (30 s)" | D12, D13: a start beyond 30 s is a failed first connection, and for a plugin server it is then cached for 15 minutes across sessions | A slow first fetch costs more than one session: the launcher must answer within 30 s whatever the download does |
| X3 | SOLUTION-DESIGN §4.10 and §10.4 name the `command` source as a candidate without its terms | D1 to D6: install-time prompt showing the command, re-run once per session in the background, 256 MiB copy limit, `cmd.exe` on Windows, link mode refused on Windows, policy switch `disableCommandPluginSources` | The comparison in criterion 3 weighs these |
| X4 | §13 F23: "official plugins ship servers via `npx`, `uvx`, `docker`, `bun run` or HTTP, none as a binary" | D7, D8: the `npm` source never runs install scripts and refuses GitHub release tarballs; an `archive` is one zip per entry, `https` only, 256 MiB | Neither source carries per-platform executables: six targets are 86 to 105 MiB each (criterion 1), so one archive with all six (about 270 MiB gzip) is over the limit |
| X5 | §13 F18 and §4.10 assume the 30 s limit bounds the session's first ask | D12: startup is non-blocking, so a session can start and the agent can ask before AskBoard's tools are listed | The `ask` tool can be absent for the first seconds of a cold session; AD-18 already covers absent tools (AskUserQuestion) |
| X6 | F35 "tinycc in output: packaging spike" | D20 and the strings found in every target (criterion 6) | tinycc is in the output on every AskBoard target, whether or not AskBoard calls `cc()` |
| X7 | AD-19 obligations name "Bun's notices" | D19 and Bun `LICENSE.md`: about 50 statically linked libraries with their own licences, among them `zstd` (BSD or GPLv2, dual) and ICU 78 | The notices file is Bun's whole `LICENSE.md` plus the LGPL texts; no GPL-only component is listed |
| X8 | §8 "native Windows gets a message naming WSL (mechanism: packaging spike)" | D2, D16: Claude Code on Windows uses forward-slash paths, `cmd.exe` for command sources and PowerShell for hooks without Git Bash | A POSIX launcher needs `sh` on Windows; without Git Bash nothing runs it, so the message cannot come from the launcher alone (criterion 11) |
