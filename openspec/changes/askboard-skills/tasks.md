# Tasks

Each task writes its tests first and sees them fail for the right reason before it implements (the repository's TDD rule). "The check" means `GITHUB_TOKEN=$(gh auth token) bun run check`, which from task 2.4 on includes `check:skills`. "Coverage" means at least 80% of lines and functions for every file the task adds or changes, read from `bun test --coverage`'s per-file table. "Regenerate" means `bun run build:skills` with the result committed in the same commit. After each task: `openspec validate --all --strict --no-interactive`, `bun run format` with `git status` showing only the task's files, the check; then tick the box with a note of about five lines (what was built, test counts, deviations) and commit in conventional form with no attribution. Appended export blocks follow askboard-implementation; versions follow askboard-contract-versioning (this change widens no set).

Order: group 0 first. Group 1: tasks 1.1 and 1.2 (`contract`) and 1.3 (`molecules`) in parallel. Task 2.1 (`tools/build/skills/fields.ts`) may start beside group 1 once task 0.2 is done; tasks 2.2 to 2.5 follow group 1. Task 3.3 (`bench`) may run at any time after task 0.3, beside groups 1 and 2; tasks 3.1 and 3.2 follow group 2, its fix tasks 2.7 to 2.14 included. Tasks 2.7 to 2.13 run one at a time, in order, since most regenerate `skills/askboard/`; task 2.12 (the spine) may run beside any of them. Group 4 last.
