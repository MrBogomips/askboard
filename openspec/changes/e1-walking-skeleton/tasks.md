# Tasks

Each group writes its tests first and verifies that they fail before it implements (the repository's TDD rule). "Check passes" means `bun run check`, with `GITHUB_TOKEN=$(gh auth token)` for the licence step.

## Parallel tracks

Two sessions build E1 at once, after one session has finished Track 0 (design decision 13). Task IDs are fixed: each session ticks only the boxes of its own track and writes notes only under its own tasks, so `tasks.md` merges without conflict.

| Track | Groups | Owns | Worktree and branch | Starts |
| --- | --- | --- | --- | --- |
| **0. Shared interfaces** | 1, 2 | The root `package.json`, `bun.lock`, `tsconfig.test.json`; every `packages/*/package.json` and `packages/*/tsconfig.json`; `packages/contract/`; `tools/check-licences.ts`, its test and `tools/licence-overrides.json`; the spine's Stack and AD-7 | `feature-e1-walking-skeleton`, branch `worktree-feature-e1-walking-skeleton` | First, alone |
| **A. Session side** | 3, 4, 5, 6, 7 | `packages/contract/` (from 3.1 on), `packages/core/`, `packages/server/`, `.claude-plugin/`, `tools/check-imports.ts` and its test, the spine's AD-1 | `feature-e1-track-a`, branch `worktree-feature-e1-track-a`, from Track 0's last commit | When 2.5 is done |
| **B. Browser side** | 8 | `packages/view/`, `tools/build/` | `feature-e1-track-b`, branch `worktree-feature-e1-track-b`, from Track 0's last commit | When 2.5 is done |
| **Integration** | 9 | Any folder, once both tracks are merged; also `.github/workflows/ci.yml`, `CLAUDE.md`, `README.md` | `feature-e1-walking-skeleton` | When groups 3 to 8 are done |

- E1 touches no other folder: `packages/compute`, `widgets`, `molecules`, `mod`, `hooks` and `bench` stay empty.
- After Track 0, the root and package manifests, `bun.lock` and the tsconfig files are frozen until Integration. A track that needs a change to them stops and asks the other session; the change lands once, in one branch, and the other branch merges it.
- Track 0 hands `packages/contract/` to Track A, which adds the agent-side sets (group 3). The sets, constants and fixtures of group 2 are the interface between the tracks: Track A changes them only with Track B's agreement, in the same way, and Track B never edits `packages/contract/`.
- **Track A's integration point** is `board-host` serving `dist/view/` (the board page, the manifest at `/m` and the chunks it names) and answering the board page over `/ws/<askId>`. Before the merge, 6.3 and 6.4 run `board-host` against Track 0's fixture manifest and the board page's half of its recorded transcripts. **The test that proves the fit** is 9.2: the conformance suite drives the real board page on the real session process.
- **Track B's integration point** is the board page talking to the real `board-host`: the token-first WebSocket, the manifest and chunk fetches with the token header, the board protocol messages and the close codes. Before the merge, 8.1 validates the built manifest against the contract's schema and 8.3's test server replays the host's half of the same transcripts. **The test that proves the fit** is 9.3: the browser tests run against the built session process in Chromium, Firefox and WebKit.
